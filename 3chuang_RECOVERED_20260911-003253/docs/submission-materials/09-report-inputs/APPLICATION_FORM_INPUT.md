## 5. 项目摘要候选（3 个版本）

### 版本 A（约 100 字）[已验证]

甬柜易算面向宁波港出口中小卖家，提供港前装柜智能决策。系统由 Web（React18+Three.js）、后端（Node.js+Express+MySQL）、微信小程序三端构成，核心为 Fast Block多约束三维装箱引擎（六类业务约束协同机制、确定性输出）与"引擎算物理、AI 判合规"的零幻觉合规架构。演示订单实现 221/221 件装入、84.51% 利用率、本地规则 WARNING / AI建议 PASS / 人工复核独立 合规。

### 版本 B（约 200 字）[已验证]

甬柜易算是一个面向宁波港出口中小卖家的港前装柜智能决策系统，覆盖"货物录入→SKU管理→柜型推荐→装箱算法→三维作业可视化→合规预审→报告导出"的完整闭环。系统采用 React18+Vite5+Three.js0.179 构建 Web 端，Node.js+Express+MySQL 构建后端，原生微信小程序+threejs-miniprogram 构建移动端。核心装箱能力由 Fast Block多约束三维装箱引擎与 Realistic4D v34.7 引擎提供，遵循 LIFO 卸货顺序、动态重心、同 SKU 聚集、堆叠安全、搬运可达性、VGM 合规六个维度的硬约束。合规采用"引擎算物理、AI 判合规"的零幻觉架构，AI 仅写建议不判定结论。演示订单 NB2026-DEMO-01 实现 221 件输入、221 件装入、84.51% 利用率、本地规则 WARNING / AI建议 PASS / 人工复核独立 合规。

### 版本 C（约 500 字）[已验证]

甬柜易算（Ningbo Port Intelligent 3D Packing System）是一个面向宁波港出口中小卖家的港前装柜智能决策系统，旨在用确定性装箱算法与本地合规规则替代人工经验装柜，降低倒箱费、退港、查验布控风险。系统覆盖"货物录入→SKU管理→柜型选择/推荐→后端装箱算法→三维坐标方案→3D装柜作业→合规预审→AI解释→人工复核→报告导出"的完整主链路。

系统采用三端架构：Web 端基于 React18+Vite5+Three.js0.179，提供 6 个核心页面（Dashboard、Cargo、Container、Twin、Compliance、Report）；后端基于 Node.js+Express+MySQL2，提供 41 个 API 端点与 4 张数据库表（cargo/container_type/packing_plan/user）；移动端为原生微信小程序+threejs-miniprogram，提供 5 个页面。

核心装箱能力由 Fast Block多约束三维装箱引擎（生产主力）与 Realistic4D v34.7 引擎提供，由 AlgorithmOrchestrator 调度器统一调度（6 个算法 ID 白名单），在 LIFO 卸货顺序、动态重心、同 SKU 聚集、堆叠与重不压轻安全、叉车/人工搬运可达性、VGM 总重合规六个维度硬约束下确定性输出（相同输入相同结果）。3D 作业通过 18 相位状态机与真实坐标驱动，程序化构建 118 部件集装箱、34 部件叉车与 4 关节人工 actor，配合 AABB 碰撞检测（tolerance=2mm）为仓库工人提供装柜蓝图。

合规预审采用"引擎算物理、AI 判合规"的零幻觉架构：本地规则引擎判定 PASS/FAIL（7 条红线），DeepSeek V4 Flash 仅撰写建议文本不判定结论，基于 TF-IDF 余弦相似度的本地法规 RAG 检索 4 份法规 JSON 17 sections，VGM 后端硬计算（相对误差≤5% 且绝对误差≤1 吨），三层合规证据链（本地规则→AI建议→人工复核）不可静默覆盖。系统支持 HTML/CSV/JSON 报告浏览器本地导出。后端累计 811 个测试（54 文件），Web 端 21 个测试文件 90 个用例。演示订单 NB2026-DEMO-01（宁波→汉堡→鹿特丹→安特卫普，40HQ）实现 221 件输入、221 件装入、84.51% 利用率、8,812 kg 装入总重、本地规则 WARNING / AI建议 PASS / 人工复核独立 合规。

## 6. 项目背景

> 注：以下为代码与仓库可证明的内部事实，外部行业数据需 Deep Research 调查 [已验证]

宁波港出口中小卖家在装柜环节长期依赖人工经验，面临空间利用率低、多目的港卸货顺序混乱、VGM 总重申报误差、重心偏移超限、堆叠事故、合规资质核查不全等问题，可能导致倒箱费、退港、查验布控等损失。现有装柜软件多侧重单一装箱算法，缺乏将确定性装箱算法、3D 作业过程可视化、合规预审三者集成的港前决策系统。

甬柜易算定位为港前（Pre-Port）装柜决策系统（非港口 TOS、非码头作业系统、非报关单证系统），后端内置 3 套货型模板（慈溪小家电、宁波文具、宁波汽配），AI 合规服务设定"宁波港 20 年资深理货长"角色，覆盖宁波港出口中小卖家、货代/理货长、仓库工人/叉车工三类目标用户。

> 外部行业数据（宁波港出口规模、倒箱费损失金额、行业市场规模等）需 Deep Research 调查 [待确认]

## 7. 解决的问题

[已验证]

1. **人工经验装柜空间利用率低**：确定性 Fast Block多约束三维装箱引擎生成科学装箱方案
2. **多目的港卸货顺序混乱**：LIFO 卸货顺序硬约束（FastBlock._checkLIFOHardConstraint），演示订单支持 3 港
3. **VGM 总重申报误差风险**：后端硬计算，相对误差≤5% 且绝对误差≤1 吨
4. **重心偏移超限运输安全隐患**：NingboPortSafetyEngine 横向≤5% 纵向≤10% 警告
5. **重不压轻堆叠事故与易碎品损坏**：maxStackLayers / checkStackingConstraints / fragile / heavy 约束
6. **合规资质核查不全**：7 红线本地规则（载重/重心/LIFO/单证/危险品 UN38.3/MSDS/IMDG/木包装 IPPC/混装禁忌）
7. **仓库工人装柜无蓝图**：18 相位状态机 3D 作业过程可视化，区分叉车与人工 actor
8. **AI 合规幻觉风险**：零幻觉架构，AI 仅写建议不判定结论

## 9. 科学原理

[已验证]

### 9.1 装箱算法
- **块优先装箱（Block-Priority Packing）**：FastBlock 将货物组合为块后装载，Realistic4D v34.7 采用 Y 轴地面优先 + LIFO + Z-Lane 屏障
- **确定性输出**：AlgorithmOrchestrator + seed 保证相同输入相同输出
- **六类业务约束协同机制**：LIFO 卸货顺序、动态重心、同 SKU 聚集、堆叠安全、搬运可达性、VGM 合规
- **多策略融合**：realistic4d-multi-strategy 融合取最优（6 算法 ID 白名单）

### 9.2 3D 可视化
- **18 相位状态机**：IDLE→OPENING_DOORS→...→COMPLETED/PAUSED/BLOCKED
- **真实坐标驱动**：x=长度，y=高度，z=宽度，货物 loadedCargo{x,y,z,l,h,w}
- **程序化构建**：118 部件集装箱 + 34 部件叉车 + 4 关节人工 actor
- **AABB 碰撞检测**：分离轴定理，tolerance=2mm
- **InstancedMesh 批量渲染**：性能优化

### 9.3 合规规则引擎
- **7 红线本地规则**：载重/重心/LIFO/单证/危险品/木包装/混装禁忌
- **VGM 硬计算**：相对误差≤5% 且绝对误差≤1 吨
- **重心偏移**：横向≤5% 纵向≤10%
- **4 法规 JSON 17 sections**：CTU Code / GB 40163-2021 / JT/T 1187-2018 / SOLAS VGM

### 9.4 AI 辅助
- **零幻觉架构**："引擎算物理，AI 判合规"，AI 仅写建议不判定结论
- **TF-IDF 法规 RAG**：余弦相似度本地检索，零外部依赖
- **三层合规证据链**：本地规则→AI建议→人工复核，不可静默覆盖
- **VLM 货物识别**：Qwen3-VL-32B 视觉模型
- **TTS 语音合成**：seed-tts-2.0
- **联网法规检索**：Tavily Search（依赖 Key，有降级）

## 10. 创新点（5 个）

[已验证]

### 创新点 1：Fast Block多约束三维装箱引擎的六类业务约束协同机制确定性输出
在 LIFO 卸货顺序、动态重心、同 SKU 聚集、堆叠与重不压轻安全、叉车/人工搬运可达性、VGM 总重合规六个维度硬约束下，通过块优先策略确定性生成三维装箱方案（相同输入相同输出）。代码证据：[backend/services/FastBlockPackingEngine.js:613] `sixDimensionalConstraints`。

### 创新点 2："引擎算物理、AI 判合规"的零幻觉合规架构
装箱物理决策由确定性算法生成，合规审核由本地规则引擎判定 PASS/FAIL，DeepSeek V4 Flash 仅撰写建议文本不判定结论，从架构上杜绝 AI 幻觉。代码证据：[backend/services/AIComplianceService.js:6]。

### 创新点 3：18 相位状态机与真实坐标驱动的 3D 装柜作业过程可视化
程序化构建 118 部件集装箱+34 部件叉车+4 关节人工 actor，18 相位状态机驱动作业流程，真实坐标驱动，AABB 碰撞检测 tolerance=2mm，区分叉车与人工两种作业 actor。代码证据：[web-dashboard/src/three/operation/operationMachine.js]。

### 创新点 4：基于 TF-IDF 余弦相似度的本地法规 RAG 检索
4 份法规 JSON 17 sections（CTU Code / GB 40163-2021 / JT/T 1187-2018 / SOLAS VGM），TF-IDF 余弦相似度本地检索，零外部依赖，配合 7 红线本地规则联动。代码证据：[backend/services/RegulationRAGService.js]。

### 创新点 5：VGM 后端硬计算与三层合规证据链
VGM 后端硬计算（相对误差≤5% 且绝对误差≤1 吨），三层合规证据链（本地规则→AI建议→人工复核），MANUAL_REVIEW action 追加到 complianceHistory 不可静默覆盖，finalConclusion 优先人工→本地规则。代码证据：[backend/services/AIComplianceService.js] / [web-dashboard/src/pages/workflows/CompliancePage.jsx]。
