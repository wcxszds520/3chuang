# PORTCUBE · CMIT 2026 规则核验与针对性优化

核验日期：2026-09-26。赛事：2026 年第十四届全国大学生数字媒体科技作品及创意竞赛。
本文件取代此前按 2025 年规则编写的升级方案。旧稿完整保留于 `artifacts/cmit-20260926/before/docs/competition/CMIT_UPGRADE_PLAN.md`。
本文是依据公开标准进行的模拟评审与工程优化，不是赛事官方评审意见，不预测奖项或获奖概率。

## 1. 结论与参赛定位

建议作品名：**智港立方 PORTCUBE——面向货物变更的可追溯集装箱装载决策系统**。
建议类别：**自主选题 / 移动与网络应用开发类赛项**；学历赛道由团队实际最高学历确定。

理由：主要成果是有业务流程、算法应用、网络接口与可运行界面的 Web 信息系统。三维孪生服务于装载决策；没有硬件原型，因此不因“智能”二字选择智能硬件类别。除非团队后续将主要创新和工作量改成沉浸式交互，否则不优先选择 VR/游戏类别。使用 AI 辅助开发也不自动意味着要报 AIGC 指定命题。

作品主线：**货物尺寸发生变化后，如何得到一份与当前输入一致、可以解释变化、明确未知事实的新装载方案。**
不以“有很多模块”“接了大模型”“能画漂亮箱子”作为主要创新论据。

判断：项目的可演示工程闭环已有基础。最影响竞争力的缺口是**学生实质贡献证明、可信的应用验证和完整提交证据**。继续堆模型数量或盲目加强视觉，无法替代这些项目。

### 算法结果应怎样表述

冻结基准曾运行 15 案例 × 5 求解器 × 2 次 = 150 次。必须区分通用几何校核和生产业务准入。
Native 通用有效 28/30；生产业务准入 10/30，其中 4 个空装、6 个非空装。不能把几何通过率写成真实业务成功率。
演示 42 件的一次宽度变更记录为 40 件保持、2 件移动，属于这个案例，不能外推成“减少 95% 搬动”或行业平均提升。
原 212 件历史方案保留，不拿视觉调整冒充求解提升。
失败只能说明当前有界搜索未找到满足条件的方案，不能宣称数学不可行。

## 4. 本次已经实施的产品优化

入口：首页“作品导览与验证” → `/review`。

1. **四步可复现路径**：输入 → 实际求解 → 演示变更 → 孪生/出运证据。按钮只导航，不覆盖已有货单。
2. **三项设计主张对应检查点**：输入变化隔离旧证据；局部修复/回退与差异；计算/模拟/现场状态分开。
3. **当前验证快照**：用户点击后读取能力状态，导出当次输入、当前方案、历史版本、父版本差异、存储与 AI 状态。
4. **旧证据隔离**：指纹不匹配时不导出 currentPlan 或当前差异；历史记录有明确历史身份。
5. **独立可核对**：输入与整体快照均提供 SHA-256，另提供本地校验命令。哈希用于完整性比对，不保证签名、防伪或第三方认证。
6. **历史证据展示**：四份精简记录有源文件路径和源哈希，标明 2026-09-26 历史性质，避免重新生成展示页就冒充重跑测试。
7. **可读的使用边界**：数据库、AI 调用、现场装箱、行业效果及学生归属分别说明；未证实项目不显示成功。

主要代码：
- `web-dashboard/src/pages/review/ReviewPage.jsx`、`review.css`
- `web-dashboard/src/domain/plan/reviewEvidence.js`
- `tools/build-review-evidence.mjs`
- `tools/verify-review-evidence.mjs`
- 路由与首页入口保持现有工作区状态。

校验下载快照：
```powershell
node tools/verify-review-evidence.mjs <下载的证据文件.json>
```

## 5. 演示安排与答辩追问

以下为约 4–6 分钟的内部策划，**不是已核验的官方限时要求**。

| 顺序 | 演示动作 | 评委应看到什么 |
|---|---|---|
| 0:00–0:35 | 一句话介绍目标用户与临时尺寸变更 | 具体业务问题，避免泛谈智慧港口 |
| 0:35–1:15 | 货物页确认尺寸、数量、搬运约束，进入规划实际求解 | 输入可改，结果由接口生成 |
| 1:15–2:15 | 木箱宽度 +100 mm；先去出运准备看旧证据失效，再重排 | 核心创新的因果链 |
| 2:15–3:15 | 对比新旧位置、选中变化货物，解释修复/回退原因 | 可追溯结果，承认哪些货位改变 |
| 3:15–4:15 | 展示模拟作业与一项待补出运证据 | 模拟不等于现场，缺证据不自动通过 |
| 4:15–结束 | 返回导览导出，说明学生分工、第三方与 AI 范围 | 工程验证与原创贡献边界 |

必须准备的问答：
- 为什么这是有新增贡献的作品，而不是 Three.js 画面加装箱库？结合三个设计主张和对应代码/实验回答。
- 尺寸变更后为何不能继续用旧方案？解释输入身份、异步请求隔离和版本证据关系。
- 为什么没有每次都局部修复？说明校核条件及全量回退；展示实际 method。
- 为什么三种策略可能得到同一结果？约束和候选搜索可能收敛，不伪造差异。
- “放得下”为什么还不能出运？几何、支撑/搬运、出运材料与现场条件分别判断。
- 没有数据库/AI 时哪些功能还有效？本机求解与浏览器工作区；服务器持久化和真实模型调用不能声称成功。
- 哪些由学生完成，哪些由 AI/开源组件辅助？提交可追溯任务、修改、审阅和测试记录，由成员现场解释。

## 6. 报名内容与材料清单

### 作品简介建议文本

智港立方面向货代、仓库与装载计划人员，研究货物信息变化后如何保持装载方案与决策证据一致。系统以货物尺寸、包装、朝向、支撑与作业条件为输入，生成可在三维场景中复核的装载方案；输入变化后主动使旧结论失效，优先尝试保留可用货位，并保留重排版本及货物差异。出运准备按事实、规则来源和责任动作组织，明确区分计算结果、模拟作业与现场未知状态。当前为可运行 Web 原型，已留存演示案例的接口、浏览器及模拟验证记录，行业效果和现场执行仍待实测。

### 创意来源建议文本

装载任务不是一次性排好箱子：包装尺寸修正、货物增减和作业条件补充会改变结果。作品将研究重点放在“变化之后怎样重新决策”，通过输入身份、不可变版本、可解释差异和证据分层，减少旧结论被误用的机会。该问题陈述来自项目设计假设，尚不等于已完成用户访谈；取得真实调研后，应补充样本、日期、原始记录与由此产生的设计改变。

### 运行环境建议文本

本地 Windows、Node.js 24、现代 Chromium 浏览器；后端 127.0.0.1:13000、前端 127.0.0.1:14173。使用 Start-Master-Rebuild.ps1 启动，项目隔离配置。真实数据库与 AI 服务需要独立配置和验证；当前浏览器工作区可保存本机演示记录。以随作品提交的实际启动说明与依赖锁文件为准。暂不宣称已提供免安装 EXE 或公网可用服务。
