# 01_PROJECT_OVERVIEW

本文用途：帮助 NotebookLM 先理解“甬柜易算”是什么、服务谁、解决什么问题，以及当前已经做到哪里。

## 项目一句话

**甬柜易算** 是一个面向宁波港港前装柜场景的智能决策系统，目标是把港前装柜从经验判断，升级为可计算、可解释、可执行、可复核的智能作业闭环。

## 项目定位

项目不是单纯的装箱动画，也不是只做货物台账的管理系统，而是围绕“货物录入、柜型推荐、约束装箱、3D 作业孪生、合规预审、法规证据、报告导出”形成一条港前装柜决策链。

在现有港口、货代、仓库系统中，很多能力更偏向柜外流转、订单管理或节点协同；甬柜易算聚焦的是进港前柜内装载这个容易被经验化处理的环节：货物是否能装、如何装、装得是否稳、是否符合进港前审核要求、现场工人能否照着执行、最终是否能导出可复核资料。

## 目标用户

| 用户 | 典型需求 | 系统提供的帮助 |
|---|---|---|
| 中小卖家 | 不熟悉柜型、包装风险和港前合规要求 | 降低录入和理解门槛，提前看到装柜边界 |
| 货代配载员 | 需要快速形成可执行装箱方案 | 获得柜型推荐、完整规划结果和约束说明 |
| 仓库作业人员 | 需要把算法结果转成现场动作 | 通过 3D 作业孪生理解路径、目标位和作业步骤 |
| 港前合规审核人员 | 需要判断 VGM、LIFO、重心、木包装、单证等风险 | 获得合规矩阵、法规证据和可复核报告 |

## 核心痛点

港前装柜的风险通常不是在系统表格里突然出现，而是藏在柜内空间里：重量分布、卸货顺序、木包装证据、单证一致性、现场执行偏差，都可能让一个柜子从“看起来能装”变成“进港前被卡住”。

对中小卖家来说，风险会表现为补资料、退运、延期或额外费用；对货代配载员来说，风险是方案返工和责任不清；对仓库工人来说，风险是现场临时调整、重货压轻货和作业不可达；对审核人员来说，风险是材料不完整、依据不清楚、难以追溯。

## 核心方案

甬柜易算的方案可以概括为六步：

1. 通过人工录入、CSV 导入和 VLM 拍照识别建立货物数据。
2. 根据货物属性和柜型约束推荐合适柜型。
3. 用确定性装箱算法生成装入、未装入、重心、顺序和可达性结果。
4. 用 Three.js 3D 作业孪生把装箱结果转成现场可执行画面。
5. 用本地法规证据库、RAG 检索和 AI 解释形成合规预审。
6. 导出 HTML、CSV、JSON 形式的装柜与合规资料。

## 当前边界

项目需要诚实表达边界：

- 统一表述为“方案结果：221/221 件已规划装入”。
- VLM 能力已接入并有样例识别通过，但仍保留人工确认，不写“无条件全通过”。
- RAG 口径是本地法规证据库和检索增强解释，不写“实时联网国标检索”。
- AI 负责解释、建议、检索和辅助录入，不直接决定物理坐标。
- 系统当前适合演示和答辩表达，不应夸大为生产级全量系统或已大规模商业化落地。

## 价值总结

甬柜易算的价值不是把人工完全替代掉，而是让港前装柜这件事提前被看见、被计算、被解释、被执行、被复核。对国赛答辩而言，最重要的记忆点是：**把每一个柜子装对、装稳、装合规。**
