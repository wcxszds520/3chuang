## 3. 原 212 件算法：先审计口径，再真正重排

### 3.2 首先核对重心分母
有一个尚未证实的根因线索：
- 历史 772 mm 平移使纵向偏移从 8.266% 变为 21.099%，变化约 12.833 个百分点。
- 对 L=12032 mm：772/L×100≈6.416%；772/(L/2)×100≈12.832%。
- 104.305/(L/2)×100≈1.734%，又与 8.266%→9.999985% 接近。
这提示历史实现可能按半柜长归一化。必须检查代码、原始坐标与所引用指导定义；不能直接把所有结果除以二，也不能未经检查宣称公式错误。
核对：求解轴向、最小角与中心坐标、旋转后的尺寸、质量加权、货物重心与整柜重心的区别、内长/外长/半长、实际单位，以及前后端/AI 是否采用同一分母。
输出重心原始毫米值、相对柜中心位移、归一化分母和百分比。百分比是偏心位置，不是“超载百分比”。
用对称布局、已知质量的一维算例、固定平移量验证公式，再对照原始 CTU 条款；工程指导、项目策略和强制条件必须分开。

## 4. 多柜分配与多客户拼柜

多客户范围先是单一操作员在本地管理多个客户的货物，不扩张为跨企业多人实时协同或交易平台。
产品不能写死单一 activeContainer 与 42/212。保留单柜流程兼容，同时建立：
客户/订单 → 货物行 → 独立搬运单元 → 装载任务 → 多个柜方案 → 柜内 placement → 执行与证据。
每件货物有稳定唯一 ID、owner/order、包装与实际外形、质量、数量展开关系、目的地/服务与时窗、约束和来源；每个柜有设备配置、状态、已分配货物、方案版本和证据。
客户归属不是物理尺寸或颜色；视觉颜色只在归属分析模式覆盖，标准模式保留真实材质。

必须完成三个真实流程：
1. 单客户多柜：一柜无法装完时继续分配到后续柜，并比较柜型组合。全量待装/已分配/未分配数量守恒。每柜重新做三维可行性验证，不能用体积相除冒充装箱。
2. 增量拼柜：客户 A 已有多柜方案，最后一柜有余量；加入客户 B 后，先核查运输服务、时窗、目的地/拆箱点、包装相容与混装政策，再检查真实可插入空间、门洞、承重、重心和卸货条件。
3. 不可拼柜：尺寸或服务不兼容、锁柜、无通道、载重/支撑不允许时明确拒绝该分配，并尝试其他柜或新柜，给出事实原因。

状态必须区分“可重排草案”“已确认但未执行”“已实际装入并锁定”“已封柜”。已锁定货物不能悄悄移动，已封柜不能自动打开。可移动对象重新规划前展示影响，确认后提交新版本，旧版本可回看。追加任务期间检测版本冲突，避免用过期方案执行。
如只有部分新货可放入，返回可装子集和未分配明细，不静默丢件。已装对象不重复计算，分柜清单包含客户归属。
不要假定普通海运拼箱会在每个挂靠港开同一个箱卸几件。明确本项目的海运共同服务/目的地拆箱点与多站点卸货演示的区别；不扩张到真实订舱、报关或交易平台。
无报价就比较柜数、配置、装入量和利用率；模拟价格必须标明演示参数，不虚构节省金额。

## 6. 作业编排：每件货物连续、唯一、接触可信

场景为有明确地面高度的本地示意作业区：集装箱 + 门区安全连接 + 右侧紧凑待装区 + 已卸暂存区 + 设备等待位。不同柜位使用独立 scene transform；业务柜内坐标不受世界摆放位置影响。
待装区按客户/包装/批次整齐分组，可只渲染代表堆垛；必须清楚标注代表数量，当前件与下一件按真实尺寸独立可见。堆垛贴地或有真实支撑，不挡门、不侵占转弯扫掠范围、不铺成巨大货物森林。
件级状态：待取 → 搬运中 → 交接中 → 已落位/已卸达。各状态数量守恒，同一货物的可见主实例只能处于一个真实位置；代理堆垛相应减计，不从空气中复制一箱。

人工：走到取货位 → 面向货物 → 屈身/抓取 → 持货步行 → 对准真实支撑面放置 → 手释放 → 空手返回。手脚接触与动作节拍由路程、姿态和目标高度驱动。禁止穿墙、踩货、漂浮、滑步冲刺、货物先到人后到。
叉车：地面底盘保持接地，轮组转动/转向，提升发生在门架/货叉；插叉后有承载关系，退出货区再转弯。门外交接与地牛接管时货物世界姿态连续，释放顺序正确。
地牛：叉孔、货叉、底轮相容；工人握住把手，推拉朝向合理，低位运输到真实位置，下降与抽叉后货物留在支撑面，不出现“货物掉下但设备已走”。
叉车能否进柜由当前设备净高/净宽、门洞、坡道承载、地板载荷、通道与工况决定，不用一刀切禁入或无限允许。剖切隐藏的壁面仍是物理边界。
遇到不可执行动作要解决设备/路径/排列/工艺，不能用一句示意就假装执行成功；外部未提供的真实设备能力保留未知，不伪造证书。允许完成其他独立改进，但该动作未解决就不能标记通过。
反向卸货必须执行相应取货、运输、交接、送达与返回，不能仅缩小/删除网格。港序和取货依赖共同决定顺序。暂停保留所有关节状态；拖动进度要确定性恢复；手动旋转停止镜头抢控。

## 7. 三维工作区和全站重新设计

采用“工作内容优先”的原创建筑：顶端简洁任务上下文，左侧可收起的订单/柜列表，中部大画布，右侧一个可切换的属性/证据/AI 检查器。右侧 AI 与其他检查器共用区域，不堆多层浮窗。
静态复核隐藏大进度条与作业状态；进入装卸才出现紧凑时间轴。默认不常驻十多个 HUD，保留极少关键事实；当前选中对象只保留一个清楚的标记，其余详情进入检查器。状态不能只靠颜色。
多柜用“全部柜位总览 → 选中某柜聚焦”的连续空间切换。相机按当前内容和侧栏可用区域适配，而不是把所有柜子挤成小玩具。告警与标签避让边缘、工具栏和主体；不靠屏外截断隐藏问题。
确定字号、行距、字重、间距、边框和状态配色系统。中文正文以正常桌面阅读为准，不靠整页缩放解决拥挤。保留必要国际缩写，英文枚举/代码/内部 ID 放到技术详情；中英文翻译不改变数据契约。

全站具体目标：
- 工作台：展示本任务客户/订单、柜数与当前可行动决策；使用质量一致的正式模型，清楚区分草稿、预览、已求解及现场确认。没有方案不能写“0 待办所以无事可做”。
- 货物录入：预设切换、客户/订单分组、包装选择、真正可编辑的数据表与适配模型预览；错误提示说清单位、原因与修复路径。导入支持任意货物数，不做 42/212 特判。
- 规划：比较柜型组合与多柜分配，清晰解释未装、剩余可用空间、必要约束和待确认资料；未求解时收起大面积空指标表，给出一个明确的生成入口。
- 出运准备：逐柜及逐客户资料状态，事实、匹配条款、责任人角色与办理入口闭环；来源阅读是来源原文/官方定位 + 项目解释分区，不把项目摘要冒充原文。
- Landing：保留高质量 Hero 资产并调整版式；包装图库从共享注册表读取，主画面展示选中包装、实尺寸与对应处理约束，不无限拉长九宫格。求解章节用可交互局部剖视或真实三维切换讲清“事实—约束—选择—落位—复核”，没有候选搜索数据就不伪造可行候选。加入真实多柜/追加客户拼柜价值演示和任务型 AI 场景。滚动是叙事手段，不用巨大空白维持动效。
- 动画：变化跟随选择、求解、交接和视角，支持打断及 reduced-motion。做正常速度下可感知且克制的过渡，不堆粒子、霓虹扫描、无限浮动和大面积磨砂。

## 8. AI 从聊天框升级为可操作任务助手

统一一个入口，提供对象上下文的轻量侧栏，并在复杂任务时展开为“对话 + 方案工作面”的大工作区。上下文只用紧凑摘要，不让重复统计卡占据半个屏幕。
输出按任务变化，不强迫所有回答套相同长模板：
- 为什么选柜：候选组合对比、关键约束、未装差异、来源及“定位柜子/比较方案”。
- 能否拼入客户 B：调用真实后端生成候选，显示新增柜数、可装货物、需移动对象和拒绝原因；可点击前后空间对比，并在确认后应用草案。
- 为什么这里有空位：定位实际区域，区分禁压、必需间距与未优化空间；用真实候选判断能否补货，不用总体积比例推断局部能装。
- 法规为什么适用：按地域、货类、运输模式和当前资料匹配来源，显示来源版本/摘录/项目判断以及责任动作。
- 当前操作怎么办：明确当前搬运主体、下一步与受限因素，提供对象定位。

AI 使用真实模型与后端工具；原始数值由系统计算，LLM 不自行捏造指标。可以让模型负责理解和解释，但证据、单位、时间、对象及版本要核对。
把“未计算”“不适用”“缺资料”“通过”“未被本次复核”分开。拒绝错误数字之外，还要拦截缺资料却说无待办、几何稳定等于运输安全、预览当正式、引用不存在、来源摘要冒充原文等语义错误。
已明确错误的局部句子可有针对性重试/重新生成；不要因为问句含 40HQ 或普通数字就整体误拦，也不要为避免拦截移除守卫。无法生成时保留真实事实与明确失败反馈。
工具进度只展示真实动作，如“读取订单”“比较柜型”“验证新增货物”，不制造假思考链、假联网或假完成。
读操作可直接执行；改业务方案先展示可撤销的候选和差异，用户应用后由后端保存版本；不能静默改原订单或已锁柜。密钥只在后端，不在前端或日志泄露；外部资料中的指令不作为系统指令执行。
实时法规查询仅在真实检索可用时提供，给出时间与来源；无联网就明确为本地资料快照，不能冒称当前最新。

## 9. 推荐执行顺序与阶段完成标准

阶段 A：恢复上下文、快照、原 212 基线与当前 GUI 复现。先审计 CoG 分母/阈值问题，同时清点优质旧资产。输出短计划后立即实施。
阶段 B：原 212 算法真实改进与正式方案持久化。小案例不得代替；允许多柜接口设计同时推进，但该问题保持独立状态。
阶段 C：Blender 主资产与 Twin 视觉核心样例。先在实际 Three.js 做出一柜、几种货物、人物、叉车/地牛的高质量片段，与旧优质版本同角度对比；不必等整站完成才看效果。
阶段 D：多柜分配、追加客户拼柜、任意货物录入和完整状态传递。必须有可交互真实数据闭环。
阶段 E：作业连续性、中文全站与任务型 AI 完整整合。禁止只留下漂亮静态样机。
阶段 F：一次完整用户路径复验、修复实际问题、保留可演示正式状态和简短交付。

阶段失败不应被模糊合并成整体成功。单个外部条件缺失不必让整个任务停止；先完成能实施的工作。真正未解决的算法或视觉问题保留在状态记录中，继续选取下一种合理方法，不写“已全部封板”。

## 10. 验证：小而有效，但不能缺失

后端既然修改，必须针对相关能力做必要回归：
- 原 212 不变输入、新旧口径对照、数量与质量守恒、越界、碰撞、支撑/承重、朝向、港序、可达性和空区分类。
- 已知小算例核对 CoG 公式；不能修改测试预期来掩盖错误。若规则经原文证明需纠正，明确记录测试变更理由和独立算例。
- 多柜同一件只分配一次；客户 B 追加后既有锁定对象不变；部分装入不丢件；封柜拒绝、版本过期拒绝、重开页面不串单。
- 原始物品/搬运中/柜内/卸达数量与可见对象一致；每类路径及暂停/恢复有针对性检查。
这些是本轮正确性检查，不是要求建设大型 benchmark 平台。通过以后不重复跑无关历史套件；小 CSS 改动不触发整套后端长测。最终做一次必要 lint/build 和主链复查。

真实 GUI 至少完成：
1. 原 212 从输入到新正式方案，多角度查看深端、门端、顶视、两侧、内部近景，确认不是平移画面掩盖空隙。
2. 至少一个可完整观看的作业案例全程播放装载与卸货；重点人工低位/上层、叉车插叉/转向/门区交接、地牛接管/落位/返回，用 1× 观看，不能只拖到结尾。
3. 多柜总览与逐柜聚焦，客户 B 追加、候选比较、应用与刷新，客户 C 不兼容反例。
4. Landing 正常滚动每一章节，包装切换、求解解释、进入工作台；不能用 capture 模式显现的内容替代普通用户页面。
5. 货物编辑取消/保存/错误输入，规划、证据、来源、办理入口，AI 至少覆盖选柜、拼柜、空位、法规和过期上下文。
6. 1600×900 与 1366×768 真实视口查看主体占比、字号、侧栏、时间轴、CTA、弹层与空状态，必要时一档更大桌面。

每次截图同时记录 taskId、planId/revision、source、containerId、数据量和资产版本。不得将预览截图配上正式报告，不得把不同任务的改进拼成同条件对比。
GUI 实看、程序验证、未测三类分开。未测 FPS 就不报 FPS。原生通道受限如实写出，实际使用 Chrome 就写 Chrome。
