# PORTCUBE 重建 v2 · 待视觉确认

状态：**AWAITING_USER_VISUAL_APPROVAL**。quality-v1 是用户已拒绝的基线。本轮完成的是版本化资产、渲染与空间装载样板；没有将新资产或新算法切为全站默认。

## 本轮如何重做

先写 PLAN.md，随后核对来源规格、实际几何和旧空位。使用 Blender 5.2.0 LTS CLI 制作、导出，Blender MCP 重新导入检查，最后通过 Computer Use 检查真实 Three.js 查看器和生产 Twin 页面。

旧版确实存在把结构变体收敛到家族基础模型的问题。新版本按“包装结构 + 原始长宽高”查找模型，颜色不参与物理规格匹配；找不到规格就显示错误，不静默套用一个其他尺寸模型。验收中还修复了候选加载前误挂载旧方案模型、错误卸载后继续访问页面面板的问题。

交付 49 个货物 GLB，覆盖 42 个不同的结构与尺寸组合，其余是既有配色配置对应的条目；另有 40HQ 和来源箱体两个 GLB。每个都有 Blender 源文件。不是 49 种包装类型，也不是 49 个全部不同的长宽高。

- 纸箱：独立箱身、封口折边、胶带、长扁及绑带结构；不再用高频纸纹和强高光制造细节。
- 木箱：封闭板材、边框、立条、斜撑和底部滑木；不同跨度重新布置构件。
- 设备箱：面板、金属型材、盖缝、凹入把手、搭扣、护角。按真实大件尺寸增加把手和加强条数量。
- 材质未提供的 WTPACK / THPACK 货物：保留中性外形，仅用于几何验证，不能据此宣称有真实包装美术。
- 柜体：灰蓝涂装、波纹钢板、门框与锁杆，按对应内腔建模。五金是简化可视化构件，不是制造商 CAD。

40HQ 内腔沿用输入的 12.032 × 2.352 × 2.698 m；名义外形 12.192 × 2.438 × 2.896 m 参考 [FESCO 官方尺寸表](https://cn.fesco.com/en/assets/containers/)。MCP 测量外形与该名义尺寸一致，见 container-validation.json。WTPACK / THPACK 内腔为 5.870 × 2.330 × 2.200 m，单独建模；外壳仅作来源箱体示意，不标成 ISO 标准柜。

渲染修复包括阴影自遮挡条纹、过度环境光、近处接触阴影、抗锯齿和纹理过滤。已知材质货物用克制的逐件明度变化帮助分辨相邻边界，该变化只是显示样式，不改变货物事实。文字压缩为“装载总览”、件数、体积利用率和柜内尺寸。

## 尺寸与比例

asset-validation.json 使用 Three.js 的实际合并几何检查全部 49 个模型：均在真实外形范围内，装配后总计 112,236 个三角形（这是全部资产之和，不是每个场景的帧内面数）。外形仅保留约毫米级的制造边缝，不放大货物、不扩大间隙、不改变 placements。

旧版抽查的可计算模型外形与放置尺寸偏差最大约 4 mm，因此不能把所有视觉比例问题都归结为“货物尺寸被改大”。Renault 本身包含 2270 × 1170 × 1270 mm 的大设备箱。新查看器同时展示原始尺寸和 1 m 标尺；扁长纸箱为 650 × 1100 × 180 mm。

最终 MCP 复核文件是 mcp-cargo-final.json、container-validation.json 和 source-container-validation.json。mcp-validation.json 是中间过程记录，最终交付哈希以最终文件和 EVIDENCE_INDEX.json 为准。

## 装载算法

新增 DenseColumnCandidate.js，以保持支撑的垂直货柱、平面束搜索、不同构造策略和补放检查生成独立候选。原 SourceBenchmarkSolver / SourceConstraintValidator 保留。优先比较体积利用率，件数作为后续指标，因此不是单纯追求装入最多小件。

| 来源实例 | 被拒绝 v1 | 本次 v2 | 体积利用率 v1 → v2 |
| --- | ---: | ---: | ---: |
| Renault 单柜派生组合 | 51 / 66 | 60 / 66 | 77.74% → 83.91% |
| WTPACK problem 18 | 61 / 75 | 61 / 75 | 84.04% → 84.04% |
| THPACK problem 84 | 54 / 69 | 58 / 69 | 79.25% → 89.48% |

Renault 是来源规格形成的单柜派生组合，不是 Renault 官方竞赛实例排名。WTPACK 本轮没有改善，保留了更好的原候选。

旧 Renault 找到了实际可补放位置，例如 SKU 119233042RN，位置 [7550, 1700, 0] mm，放置尺寸 [1200, 1000, 295] mm。void-insertion-audit.json 最多记录 20 个可行位置，这不是多装 20 件的证明。

对三个新候选，在有界最大空盒及支撑面坐标检查范围内，没有找到剩余单件可直接补放的位置。这个检查不排除通过多件搬移、其他组合或更长搜索获得更高利用率，**不构成全局最优或 100% 装满的证明**。补放阶段仍有时间预算，不能宣称整个过程完全确定性。

本轮按用户要求放宽重心、承压、层间重量顺序及作业约束；保留真实数量、尺寸、允许方向、边界、无重叠和底面支撑。Renault 在原始约束复核中仍有 SOURCE_RULE_UNSUPPORTED / LAYER_WEIGHT_ORDER，不具备直接出运结论。完整原约束结果保留在候选 JSON 内。

原生 212 件页面保留全部旧坐标、件数和 79.43% 体积利用率。该批全部装入后仍不足整柜容积，不能凭空补货或放大模型把余量伪装成满柜。

## 验证与限制

- 相关前端原有 12 项回归通过；新增加的颜色别名与严格规格拒绝 2 项测试通过。
- 三个真实候选逐件匹配来源数量、原始方向与尺寸，几何验证通过；另用明确标注的合成 2×2×2 用例验证满铺、碰撞、越界和输入不变。合成用例不计入外部数据成绩。
- 生产前端构建与独立查看器构建通过。
- Computer Use 检查原生 212 件、Renault、WTPACK、THPACK 的实际页面，单件新旧对照、长扁规格、货墙近景与点选；旋转、停止、复位可用。未逐一人工审查全部 49 个模型，未做所有业务页面的新一轮全覆盖验收。
- 查看器前台曾显示约 66–72 FPS，其他时刻有明显低帧率，受前后台状态影响；没有稳定帧时统计或整站性能达标结论。
- 新算法当前是可重复检查的独立候选模块与预计算样板，尚未替换通用导入后的默认计算 API；不能把本轮视作任意外部 CSV 上传、求解、持久化全流程均已验证。
- 视觉仍是待审工业样板，纸箱材质较简洁、部分远处五金不易辨识。没有声称“惊艳”“摄影级”或 VISUAL_READY。

所有修改位于 recovered 工作区。835 个旧审计基线文件中 818 个一致，17 个累计 UI 变动包含本轮之前的修改，不能称为本轮新增 17 处。5 个任务载荷和 5 份已有计划 GET 内容复核一致；未通过写入 API 修改它们。这是所列证据范围内的验证，不是整个数据库逐字节不变的证明。

## 如何查看与复核

先打开 comparison.html，所有图片均在同包 screenshots 中。实时生产链接依赖本机既有 16273 / 13100 服务。

viewer 是独立构建的 Three.js 查看器。运行 `python serve-viewer.py` 后打开 http://127.0.0.1:16683/rebuild-review.html；其中 GLB 和贴图已随包提供。已从该打包目录独立启动并用浏览器复核木箱显示。其“打开实际装载”链接指向既有本机服务。直接双击该模块页面可能受浏览器本地文件限制；comparison.html 静态对照可直接打开。

blender 内含建模脚本与 .blend；source / before 是本轮修改和既有文件前版本。脚本仍采用本机工作区路径，移至另一机器需修改路径并准备所列输入和 Wood058 纹理。源码交付是对现有项目的补丁包，不是完整独立应用仓库。

input-*.json、算法与空位检查 JSON、模型包围盒、MCP 测量、构建日志、截图 AX 文本及 EVIDENCE_INDEX.json 构成可复核索引。上一版资产、数据、报告保留，未经视觉确认不批量部署。
