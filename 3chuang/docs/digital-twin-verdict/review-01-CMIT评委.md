## 3. 90 秒印象诊断 + 怀疑点清单

**初步印象原话：**"概念我秒懂——装柜优化 + 法规溯源，而且它居然如实把 AI 答错也亮出来了，这点比一堆包装项目诚实。但那个 3D……半透明集装箱里一堆彩色块，像在摄影棚里摆积木，不是港口现场。我说不出这是'数字孪生'还是'示意图'。"

**怀疑点清单：**
- 一个纸箱 2 MB / 107 网格、集装箱 8 MB / 14.7 万面——用离线渲染标准喂实时 Web
- 主场景与 GLB 两套资产线并存，风格不统一
- 默认半透明箱壁 + 网格线弱化货物辨识（团队自己已承认）
- `RoomEnvironment` 影棚环境，不是港口天空，是"积木感"主因
- 212 件 79.43% 与 42 件 51.87% 两案例口径和"主案例"不清
- 法规溯源页面日期可能只是当天日期，未必实时检索
- ESP32 仅 HTTP 轮询，"物联网"叙事偏教学级
- AI 复杂问题需重试两次才成功返回
- 文案暴露 `placement` / `语义` 等实现术语，专业感打折

## 5. 真实性审查结论

- **两案例口径**：212 件 79.43% 为基线案例，42 件 51.87% 为当前正式演示。差异源于装满程度，**非同一口径**，答辩必须明确"主案例 = 42 件"，否则按"数字打架"从严处理。
- **法规溯源**：Source Reader 能打开真实 IMO 页，但团队自述未实时检索、日期或仅为当天。验证法：现场断网演示降级行为。
- **ESP32 物联网**：HTTP 轮询在竞赛演示够用，但"物联网数字孪生"叙事需降级为教学级。
- **正面强证据**：demo 标 `DEMO_DATA`、AI 事实守卫拒绝未知数字、失败如实展示——已主动抵消大量包装嫌疑。
- **结论**：未发现把 demo 包装成实盘的硬性证据（团队已主动标注），但"出运准备已就绪""纵向偏移口径"存在"看起来像真"的误导风险点，需现场澄清。

## 6. 3D 呈现对评分影响的量化

- **演示与表达**：当前 5/10，损失约 3 分。修好（实体容器 + 港口环境光 + 构图重做）后估 8/10
- **技术方案合理性与深度**：当前 14/20，3D 失控扣约 2 分。修好后估 16/20
- **合计 3D 直接损失约 5 分**

推理：资产压缩闸门 + 补批处理 + 换环境光照，可在 1–2 天把 draw call 收回 800 内、并消灭"积木感"，成本极低、提分高。修复后总分约 **68 → 73**。注意：3D 只拖第一层（几何孪生），第 2/3/4 层已达标，所以是"补一层"不是"重做"，ROI 极高。

## 7. 保守版 / 激进版路径

**保守版（2 周内，按 ROI 排序）**
1. 压缩闸门 `gltfpack -cc -tc -kn -km`，并补调 `batchStaticAsset`
2. 换港口环境光（`environmentIntensity` / `HemisphereLight` / `exposure` / `Fog` / `rim` 五个数）
3. 容器默认实体化，线框/剖切降级为模式开关
4. 明确主案例 = 42 件，界面标注 212 件为对比基线，统一利用率口径
5. 文案去实现术语，出运准备加"仅静态证据/待现场验证"标注
6. 用 Q1–Q10 做答辩 30 秒口播预演；现场演示断网法规溯源降级

**激进版（1–2 个月）**
1. 升级 three r185，`EffectComposer` → `RenderPipeline`，评估 WebGPU + WebGL2 兜底
2. 三档 LOD + 相机预设重做
3. Tripo 生成 hero 件 → Blender 精修 → 压缩接入，仅覆盖约 20% 资产
4. 统一资产管线，程序化兜底与 GLB 风格一致
5. 遥测注入接口，几何孪生接真实数据源
6. 商业闭环：VGM 补录 → 承运/码头申报（哪怕 mock），争取一家真实货代试用
7. 求解器输出可解释优化依据报告

**一句减法忠告**：别再加功能。先把 478 个可省 draw call 砍掉，把 5 个光照数值改对，把"已就绪"改成"待验证"，把 42 件讲成一个故事——这三件事比任何新模块都更提分。
