## 三、修复方向（已定的分层，不再讨论）

```
Cargo（货物定义）    → 原始尺寸、重量、数量、允许方向集合   ← 不在这层写死最终朝向
Preview item        → 为展示选择的预览姿态，标 PREVIEW      ← 默认演示走这里
Placement           → 每个物理件实际采用的位置与方向         ← 正式求解走这里
```

- **默认演示**：由预览生成器按明确允许方向造姿态，标 `PREVIEW`，不写回求解选择
- **新生成的正式方案**：由求解输出适配器**逐件**提供实际方向
- **历史方案缺字段**：仅在来源身份 + 原始尺寸 + 最终尺寸 + 有效许可集合能**唯一证明**时重建；有歧义或冲突就报错
- **`placementAxisMap({})` 必须继续抛错**（严格反例保留）

## 四、接入内核时必须守的边界

**问题类型不能混用**

| 类型 | 可用范围 | 不能理解成 |
|---|---|---|
| `box` | 一般三维箱件的几何、方向、已支持载重 | 自动具备承压 / 支撑 / 港序 / 作业 / 系固 |
| `boxstacks` | **同底面 + 同堆叠标识**的柱结构 | 任意大小箱体的混合支撑 |
| `irregular` | **二维**排样 | 三维异形 Mesh |

**三条接口陷阱**（已列入必测）
1. **朝向空集合不能传六个 0** —— 上游"无合法方向"会被第三方默认方向变成"可以"
2. **Y/Z 竖直轴不同** —— 项目 X 长 / **Y 竖直** / Z 横向；PackingSolver 默认 **Z 竖直**。显式双向映射 + 三边不同的箱子测六种方向
3. **几何更好 ≠ 业务通过** —— box 的高利用率不代表执行了 WTPACK 的接触压力模型

**版本冻结（我补的，防止以后查不清）**
- 预编译二进制**只有 `latest`**，每次 master 提交重建，**不是版本化 release**
- 版本化 release（v1.1.0 / v1.0.0）**只有源码，没有二进制**
- → 下载时归档**三样**：二进制 + SHA-256 + 对应 commit（`9bfb943`）；adapter 里校验哈希；报告写清"测的是 master@9bfb943 的 CI 构建，不是 v1.1.0"
