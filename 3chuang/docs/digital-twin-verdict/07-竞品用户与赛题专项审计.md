我前三轮把绝大部分精力放在 **3D 渲染质量**（draw call、材质、光照、雾、各向异性）。**靶子打错了。**

CMIT = **全国大学生数字媒体科技作品及创意竞赛**。赛区评审评分表（100 分）原文：

| 维度 | 考察内容原文 | 分值 |
|---|---|---|
| 选题策划 | 符合赛项主题、主题鲜明、素材新颖、内容连贯、图文清晰 | 20 |
| **视觉效果** | **版式设计美观、色彩搭配合理、字体应用恰当、文字处理规范** | **30** |
| **互动体验** | **界面设计友好、操作方便、互动性强、体验效果好** | **30** |

| 现场演示 | 作品能在现场演示成功，各模块使用流畅，无明显 Bug | 10 |

**「视觉效果 30 分」考的是平面设计四大项——版式、色彩、字体、文字规范。不是 3D 渲染逼真度。**
**「互动体验 30 分」= 界面友好、操作方便、互动性、体验效果——我前三轮一个字都没提。**

也就是说：**60 分的主战场里，我此前只覆盖了「3D 观感」这一个子项，漏掉了版式/色彩/字体/文字规范/交互体验**。这是本文档最重要的纠正。

另外两条决定生死的机制（来自既有 `CMIT_UPGRADE_PLAN.md`，我已核对）：
- **赛区网评（网评）只看材料**：文档 + 5~10 张图 + **≤5 分钟视频**。**视频质量决定能否出赛区**——这是一条生命线，我此前完全没提。

## 第一部分　回答用户的三问

### 问题 1：卖给谁？他为什么愿意买？解决什么问题？

**项目现有答案**（`USER_RESEARCH_REPORT.md`）：卖给**宁波中小外贸企业业务员/老板**（核心付费决策者），理由是"少用柜省海运费 + 合规防损"，痛点锚点是美西 40 尺柜 3,000~5,000 美元/柜、倒箱费 800 元/次、VGM 不符罚款 1,000~30,000 元。

**我的评审：方向对，但存在三个结构性漏洞。**

**1.1【结构性问题】付费方与使用方不是同一个组织**

报告把画像 A（外贸企业老板）定为"核心付费决策者"，画像 C（装柜师傅）定为"实际执行者"。但在真实链条里：

```
外贸企业（货主）→ 把货送到货代仓库 → 货代/仓库安排装柜 → 装柜师傅是货代的员工
```

**装柜动作发生在货代的场地、由货代的人做。** 外贸企业买了软件，装柜的不是它的人。结果是：
- 外贸企业没有能力强制执行方案
- 货代没有义务使用客户的软件
- 买了软件 → 没人用 → 续费不成立

**这是"买了不用"型产品的经典死法。** 报告没有识别这个矛盾。

**1.2【利益冲突】"少用柜"对货代是负收益**

报告的核心卖点是"少用柜=省海运费"。但：
- 柜子减少 → 货代的装柜费、报关费、THC 代理费、拖车费**全部减少**
- **货代没有动机帮你少用柜**

系统如果卖给外贸企业当"监督工具"，就是**让客户去挑战服务商的利益**——落地时会被货代消极抵抗。如果卖给货代，则与自身收益冲突。

这个矛盾必须正面解决。可选解法：
- (a) 卖给**外贸企业**，定位为"订舱前的决策工具"（只影响订柜数量，不碰货代装柜动作）— 最可行
- (b) 卖给**承担 VGM 申报责任的托运人**，定位为"合规预审工具"（法规红线，货代也怕）
- (c) 与**船公司/码头**合作，作为内部工具

**建议选 (a)+(b) 组合，并把"作业复核"从 MVP 里砍掉**（因为作业复核恰好是货代的领地）。这直接回答"卖给谁"。

**1.3【取舍缺失】三个画像 = 三套需求 = 一个产品**

| 画像 | 诉求 | 对应界面 |
|---|---|---|
| A 外贸老板 | 1 分钟出柜数与柜型 | 报价助手 |
| B 货代操作 | 可申报的装载明细 | 单证/合规 |
| C 装柜师傅 | 按序作业清单 | 作业指导 |

**三个角色的信息需求完全不同，MVP 不可能同时满足。** 现有产品把三者平铺（工作台/货物/规划/孪生/出运准备），导致**任何一个角色都找不到自己的入口**——这也正是"互动体验 30 分"的失分根源。

**必须做减法：MVP = 画像 A 的"报价助手"（出口） + 画像 B 的"合规预审"（保险）。C 砍掉或降级为"可导出 PDF 作业单"。**

### 问题 2：具体使用者是谁？他关心什么？你解决什么痛点？

**项目现有答案**：画像 B（货代操作/客服）关心"数据不准被查验、被客户质疑"；画像 C（师傅）关心"凭经验、装错顺序"。

**我的评审：痛点是真实的，但"关心的问题"和"愿意付出的动作"被混淆了。**

- 货代操作**关心**的是"不要被海关布控、不要超期、不要被客户投诉"——本质是**免责**。
- 但"免责"的解法不是看 3D 孪生，而是**一份能直接提交的单证数据**。
- **3D 数字孪生对 B 和 C 都不是刚需**：B 要的是数字，C 要的是顺序清单。

**这是一个尖锐的自我质疑：项目的技术亮点（3D 孪生）恰好不是任何画像的刚需。**

3D 孪生的真实价值场景只有两个：
1. **说服客户/评委**（对外演示）— 这是竞赛价值，不是商业价值
2. **装柜前的方案确认**（销售与客户之间的沟通工具）

**建议把它明确定位为"销售沟通工具"**，而不是"作业工具"。这样反而更诚实，也更容易讲清价值。

## 第四部分　算法真实性：我实测出的最严重问题

### D1【本次审计最有价值发现】算法主动把重心停在限值线上，零安全余量

**实测三个数据集的纵向重心偏移**（我的独立复算与系统报告值完全一致，证明计算本身无造假）：

| 数据集 / 箱型 | 货物 x 范围 (mm) | 实测纵向偏移 | 精确等于 |
|---|---|---|---|
| smallBatch / 20GP | 2225 → 3175（**居箱正中，前后各空 2.2 m**） | 4.999992% | **5.0000%** |
| mixedCargo / 20GP | 84 → 5884（几乎占满全长） | 9.999992% | **10.0000%** |
| mixedCargo / 40HQ | 2197 → 11297 | 4.999995% | **5.0000%** |

反算证明：偏移量分别精确等于 294.9mm（=5%×5898）、589.8mm（=10%×5898）、601.6mm（=5%×12032）。

**根因**（`services/packing/EndGapCompaction.js:17-19`）：

```js
const half = container.innerLength / 2;
// Round toward the allowed interval, never across its boundary.
const shiftX = Math.ceil(Math.max(-minX, half - container.innerLength * limitPercent / 100 - cog.x) * 1000) / 1000;
```

`LaneStackRepacking.js:58` 同款逻辑。**算法在主动平移货物，使重心偏移精确落在 5%（或 10%）的指导限值上。**

**为什么这是严重问题：**

1. **零安全余量**：把设计点精确放在限值上，等于安全系数 = 1.0。任何实际偏差（地磅误差、包装吸湿、装载工人偏差）都会立即越线。安全工程的通行做法是取限值的 **60~70% 作为设计目标**，限值只作"绝不可越"的红线。
2. **动机可疑**：这是"为了让指标通过验收"而优化，不是"为了航行安全"而装载。海运/物流背景的评委一眼能闻出味道。
3. **它自己承认不提高利用率**：`evidence.limitation` 原文——**"空白转移到门端，总容积利用率不变"**。也就是说，**压实深端不提升任何收益，纯粹是把重心推到限值**。
4. 这解释了为什么 212 件案例的纵向偏移是精确的 **10.000%**。

**三个致命读数：**

1. **largeBatch / 40HQ：600 件货理论只占 39.8% 箱容——空间绰绰有余，算法只装进 137 件（22.8%）。** 这是算法失效，不是货量问题。
2. **largeBatch / 40HQ 纵向重心偏移 33.97%**，是 10% 限制的 **3.4 倍**，也是安全引擎 CRITICAL（15%）的 2.3 倍。
3. **mediumBatch / 20GP：理论占 44.36%，只装进 59.3%。** 同样空间够却装不进。

**CMIT plan 记录的"慈溪利用率 39.06%"已改善**（现 40HQ 实际占用 53.79%），但 largeBatch 是新的、更严重的失效案例。

**评委能戳穿的方式**：现场让系统跑一次大批量场景，等 3 分钟，然后看到 600 件只装进 137 件。

### D3　重心超限永不阻断（前一轮已发现，此处并入）

`DeterministicComplianceEngine._cogRow` 返回 `pass ? PASS : WARNING`，**永不 FAIL**。横向偏移 10.17%（超 5% 一倍）只显示"93 分"。

### D4　无垂向（Y）重心约束

`compliancePolicy.cog` 只有 lateral/longitudinal 两个维度。堆垛重心高度直接决定船舶 GM 稳性，**完全缺失**。

### D5　"AI 真实性"叙事存在张力（新发现）

实测仓库内存在：
- `backend/config/ai-offline-responses.js` —— **离线预置回答**（含"慈溪家电专用方案"等成套话术）
- `miniprogram/data/demo-precomputed-plans.js` —— **预计算方案**

项目对外叙事是"AI 真实调用、失败如实展示失败"。**如果演示时走到离线预置分支，会被认定为"预录回答"。** 必须明确区分并显式标注（"离线示例"），否则真实性叙事反噬。

## 第六部分　一句话结论

> 项目的**技术底子和材料扎实度是真优势**（用户调研有来源、成本锚点齐全、3D 已是产品级），
> 但在 CMIT 这套评分表下，**你把 60 分的主战场（视觉效果 + 互动体验）当成了技术竞赛来打**：
> 平面设计规范、字体、文案、交互引导基本没做，而 3D 渲染质量被反复打磨。
>
> 商业上有两个没被识别的结构性矛盾：**付费方与装柜方不是同一个组织**、**"少用柜"与货代利益相反**。
> 这两个矛盾不解决，"卖给谁"永远答不清楚。
>
> 算法上真正该修的不是精度，而是**安全哲学**：找到的"重心精确停在限值"不是巧合，是代码在主动把安全边际压到零。
