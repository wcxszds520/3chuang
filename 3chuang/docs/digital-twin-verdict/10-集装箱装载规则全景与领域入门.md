# 集装箱装载的规则全景：从法规到实务（领域入门）

> 日期：2026-09-18
> 目的：回答"六维约束是不是完全错了 / 港口到底管不管箱内 / 货代真正在优化什么 / 通用港与国外港怎么做"
> **本文首先纠正我上一轮的一处过度简化。**

---

## 第 0 节　先纠正我自己上一轮的过度简化

上一轮我说"港口只查重量，不检查箱内"。**这句话对"闸口检查"这个环节是准确的，但作为结论是误导的。**

正确的机制是：

> **这套体系不是靠"检查"来执行的，而是靠"责任与事后追责"来执行的。规则在内，检查在外。**

具体讲，箱内装得对不对，**在闸口没人看，但会在下面三个地方真实地反噬你**：

| 环节 | 会发生什么 | 需不需要有人"检查" |
|---|---|---|
| **吊装作业** | 重心偏了，标准吊具（四角吊点）起吊时箱体会倾斜、甚至脱出导槽、碰撞、倾覆 | **不需要检查，物理后果直接发生** |
| **拖车运输** | 重心偏前/偏后 → 轴载超限 → 交警查、车损、急刹货移动 | 部分靠路检 |
| **航行途中** | 货移动 → 箱体受损 → 船舶配载假设失效 → 堆垛倒塌 | 事故后调查 |
| **事后追责** | 货损索赔、保险拒赔、法院认定责任 | **法院与保险人拿 CTU Code 当"尽职标准"衡量你** |

**CTU Code 效力的精确表述**（英文源原文）：

> "It is **not legally binding on its own**, but is **recognized by courts and insurers as a standard of due diligence**."

所以：**没人检查 ≠ 可以不管。** 它是"自证合规"型的规则体系——你不需要向谁证明，但出事时你必须能证明。

## 第 1 节　三条强制线：全球通用的框架

不管哪个国家的港口，集装箱运输的强制约束只有三条线：

| 强制线 | 规范 | 约束什么 | 违反后果 |
|---|---|---|---|
| **① 重量** | **SOLAS 第 VI/2 条**（2016-07-01 起强制）+ 各国落地法 | **VGM（验证总重）必须在装船前申报**；无 VGM **不得装船** | 拒装、罚款（中国《船舶安全监督规则》第 47 条：误差 **≤5% 且 ≤1 吨**；未取得验证信息或超最大营运总质量，承运人不得装船） |
| **② 危险品** | **SOLAS 第 VII 章 + IMDG Code** | 分类、包装、标记、**隔离表**、船上积载位置 | 刑事/行政处罚，拒运 |
| **③ 箱体** | **CSC 安全公约** | 集装箱本体有安全合格牌（ACE/P）且在有效期内 | 拒收 |

**这三条是"法定红线"，全球一致。**

### 其余规范的性质

| 规范 | 强制？ | 作用 |
|---|---|---|
| **CTU Code**（IMO/ILO/UNECE，2014） | **非强制**（IMO 官方：non-mandatory；行业源：legally non-binding, not a treaty） | 装箱与系固实务标准；经 **IMDG/ADR** 引用而产生间接约束力；**索赔与诉讼中的"尽职标准"** |
| **ISO 668 / ISO 1496** | 标准 | 箱型尺寸、额定重量、**地板承载与点载荷**；被 SOLAS 通过 CSC 铭牌 MGW 引用 |
| **ISO 6346** | 标准 | 箱号编码与标记 |

**关键理解**：CTU Code 是"实务层"，三条强制线是"法层"。**CTU Code 管的是"怎么做才对"，强制线管的是"不做就上不了船"。**

### VGM 是怎么来的（理解它为什么这么严）

2007 年 **MSC Napoli** 事故：660 个集装箱里 **137 个实际重量比申报高 3 吨以上，最大偏差 20 吨**。调查结论原话：

> "Container shipping is the only industry where the weight is not known."

这直接催生了 2016 年强制的 VGM。据世界航运理事会，**全球平均每年约 3,000 个集装箱落海**，重量分布错误与申报不实是主因之一。

## 第 2 节　你项目最关键的遗漏：CTU Code 的 **60/50 规则**

这是我这次核查中**最重要的发现**，也是你项目**完全没实现**的东西。

CTU Code 对重量分布给的不是一句"重心要居中"，而是一条**可直接执行的量化规则**：

> **货物总重量的 60% 必须放在集装箱长度的中间一半（50%）范围内。**

具体解读（以 40ft 为例，内长 12.03m）：

```
|---门端 1/4---|--- 中间一半（50%）---|---前端 1/4---|
   最多 20%            至少 60%              最多 20%
   (轻货)            (主体重量)              (轻货)
```

**目的**：让重心落在**距几何中心 ±5% 箱长**以内。

| 箱型 | 内长 | ±5% 对应 |
|---|---:|---:|
| 20GP | 5,898 mm | **±295 mm** |
| 40GP/40HQ | 12,032 mm | **±602 mm** |

**±5% 的真实目的是三个物理后果**（原文）：

> "Exceeding this tolerance means that when the container is lifted by a standard spreader (which grips the container by the upper corner elements exactly in their spread), a **dangerous tilt** will occur. The container may deflect so much that it **falls out of the spreader guidance, collides with surrounding containers, or overturns completely**."

1. **吊具起吊倾斜**（最致命）
2. 拖车轴载超限
3. 急刹车/航行中货移动

### 和船舶稳性的关系（这一点很反直觉）

我国《国际航行海船法定检验技术规则》（2020）明确规定：

> **"计算集装箱船的稳性时，每只集装箱重心垂向位置应取在集装箱高度的 1/2 处。"**

也就是说：**船舶稳性计算把每个集装箱当作一个质点，重心固定在箱高一半处——箱内实际重心位置不进入计算。**

这解释了两件事：
- 为什么船公司/港口**不需要**知道你的箱内布局（他们假设了个标准值）
- 但正因为是"假设"，**如果实际重心明显偏离 1/2，船舶的稳性计算就是错的，而这个误差的风险由装箱方承担**

### 所以你项目的错在哪（精确定性）

你项目用的 **5%** 不是拍脑袋，它确实对应 CTU Code。**但两处定性错了**：

| 错误 | 具体表现 | 正确做法 |
|---|---|---|
| **① 把指导当红线** | 5%/10% 在同一层做 pass/fail 门禁 | 5% 是"目标区间"，不是"红线"。红线是"吊装安全"与"不导致事故" |
| **② 把约束当目标去逼近** | `EndGapCompaction.js` 把重心**精确推到 5%/10% 限值** | 60/50 规则的精神是**让重量集中在中间**，目标应该是**接近 0**，不是贴住边界 |

**而且你漏掉了 60/50 规则本身**——这是一条比"重心偏移百分比"更实用、更容易向工人解释、更容易验证的规则。**建议直接把它做进算法与界面**：

- 算法层：把"60% 重量落在中间一半"作为**硬性布局偏好**（生成时引导）
- 界面层：用三段色带可视化（前端 1/4 / 中间 50% / 门端 1/4），直接显示各段重量占比

这比显示一个"纵向偏移 4.999992%"要**专业得多、也好懂得多**。

## 第 3 节　六维约束逐条定性（回答"是不是完全错了"）

**不是完全错了。内容都对，错的是"把不同性质的约束放在同一层、赋予同等强制性"。** 正确做法是分四类：

| 你项目的约束 | 正确定性 | 依据 | 违反后果 |
|---|---|---|---|
| 碰撞不重叠 / 箱内包络 | **物理硬约束** | 几何 | 装不进去（物理上不可能） |
| 总重 ≤ 箱额载 | **法定红线** | CSC 铭牌 MGW + SOLAS | 拒收、不得装船 |
| VGM 数据完整可核验 | **法定红线** | SOLAS VI/2 + 中国 47 条 | 不得装船、罚款 |
| 危险品隔离 | **法定红线** | IMDG（强制） | 刑事/行政处罚 |
| 堆叠承载不超限 | **合同/物理硬约束** | ISO 1496 地板承载 + 包装承载 | 压坏货 → 索赔 |
| 地板点/局部载荷 | **合同硬约束** | ISO 1496 点载荷 | 箱底损坏 → 索赔 |
| **重心偏移 5%（60/50 规则）** | **实务指导（尽职标准）** | CTU Code Annex 7（非强制） | 吊装事故、货损、索赔时被追责 |
| **港序 LIFO** | **商业偏好** | 无任何法规依据 | 倒箱费（成本），不违规 |
| 空间利用率 | **商业目标** | 无 | 多花运费（成本） |
| 设备适配（叉孔/地牛） | **实务约束** | 现场作业现实 | 装不了（作业层面） |

**结论一句话：你项目里真正属于"法定红线"的其实很少（总重、VGM、危险品、CSC）；大部分是实务指导与商业偏好。把后者当前者，可行域被压到近似空集——这就是装载率崩塌的规则层原因。**

## 第 4 节　货代真正在优化什么（回答"是不是放进去就好"）

**绝对不是"放进去就好"。** 而且你提到"**多柜多拼柜**"——**这个直觉非常准，那确实是货代最有价值的一块。**

真实的货代装箱决策链：

### 4.1 装箱前（决策成本最高的部分）

| 决策 | 目标 | 影响的钱 |
|---|---|---|
| **算柜数**（体积 + 重量双约束） | 用最少柜数装完 | **一个柜 = 数千美元海运费**，这是最大单项 |
| **柜型选择** | 20GP / 40GP / 40HQ / 45HQ / 开顶 / 框架 | 重货宜 20GP（轴载），轻抛货宜 40HQ（容积） |
| **FCL 还是 LCL（整柜 vs 拼柜）** | 何时拼柜更省 | 拼柜按立方计费，比整柜便宜但时效差、风险高 |
| **多港货分配** | 哪个柜装哪些目的港 | 分配错了 → 倒箱费 + 二次开封 |
| **重轻货搭配** | 避免单柜超重或亏舱 | 超重拒收 / 亏舱多花钱 |
| **危险品可否同柜** | IMDG 隔离表 | 违规 = 刑事 |
| **客户分组** | 同客户尽量同柜 | 清关便利、单据简化 |

### 4.2 装箱时

| 决策 | 目标 |
|---|---|
| 装柜顺序 | 重底轻上；**先装远港、后装近港**（LIFO） |
| 加固方案 | 空隙大小决定系固材料与工时 → 加固也是成本 |
| 特殊货处理 | 易碎、不可倒置、超长超重、需温控 |

### 4.3 装箱后

VGM 申报（称重法/累加法）→ 封条 → 拍照留证 → 单据一致性（报关数据必须与实物一致）

### 4.4 装船（货代不控制，但要配合）

船公司配载 → 按 VGM 做整船稳性 → 箱位分配 → 危险品位置

### 4.5 所以"算法该优化什么"

**你项目现在优化的是"单箱空间利用率"，而货代真正在优化的是"总成本"。两者不是一回事。**

举例说明差在哪：
- 方案 A：3 个柜，平均利用率 85%
- 方案 B：2 个柜，利用率 92%，但有 1 批货要延到下个航次

**A 用了 3 个柜，B 用了 2 个柜。即使 A 的"利用率"更整齐，B 才是货代要的。**

**这是一个可以立刻用上的产品洞察**：把优化目标从"最大化利用率"改成"**最小化柜数与总成本**"，这会让你的系统一下子贴近真实业务。

## 第 5 节　通用港与国外港：怎么考虑与设计

### 5.1 全球框架是一致的，差异在"落地方式"

| 国家/地区 | 落地方式 | 特别注意 |
|---|---|---|
| **中国** | 《船舶安全监督规则》第 47 条落地 VGM；海事局监管 | 码头地磅自动筛查，超重无通融 |
| **美国** | SOLAS 由 USCG 执行；另有 **49 CFR**（危险品）；**CBP** 查验 | 内陆运输轴载限制严；查验可能开箱 |
| **欧盟** | SOLAS + **ADR**（公路，强制）；各国 PSC | ADR 对公路段装箱有强制要求，CTU Code 通过它产生约束力 |
| **澳大利亚** | 检疫极严（木质包装、土壤、生物安全） | IPPC 标识不达标直接退运 |
| **日本/韩国** | PSC + 国内法 | 对系固要求较细 |

**共同点**：都通过 **SOLAS + IMDG + CSC** 三条线落地；**CTU Code 是共同参考的"实务标准"**，ISO 668/1496/6346 是共同的技术标准。

### 5.2 一个重要的行业事实

> "**Misidentifying the center of gravity causes 23% of cargo damage claims in container shipping.**"
> （来源质量中等，仅作量级参考）

以及 2013 年 **MOL Comfort** 号断裂事故（集装箱堆垛累积重心对船舶稳性的影响）——这类事故推动了堆垛重量与系固规则的收紧。

**含义**：箱内装载确实"没人查"，但它是**货损与事故的高频源头**。这就是为什么 CTU Code 值得作为卖点。

## 第 6 节　给你项目的直接结论

| 问题 | 答案 |
|---|---|
| 我们拿法规做的六维约束，完全错了吗？ | **不是。内容都对，定性错了。** 你把"实务指导"和"商业偏好"当成了"法定红线"，四类约束压成一层。正确做法是分**物理硬约束 / 法定红线 / 实务指导 / 商业偏好**四类，只有前两类做 pass/fail |
| 港口根本不用考虑里面，重量不差就行？ | **闸口确实只看重量（VGM + 总重）。** 但"没人检查"≠"可以不管"：吊装倾斜、轴载超限、航行货移动是**物理后果**，货损索赔时 CTU Code 会被当**尽职标准**追溯。**规则在内，检查在外** |
| 货代考虑装箱就是"放进去就好"？ | **完全不是。** 货代优化的是**总成本**（柜数、柜型、拼柜决策、加固工时、倒箱风险），不是"利用率"。**你项目优化的是后者的一个子指标** |
| 还是主要考虑多柜多拼柜？ | **你的直觉很准**：柜数与拼柜决策确实是货代最值钱的一块（一个柜就是数千美元）。但它是**另一个层面的问题**（多柜规划），与你现在的"单箱装载"是两层，需要分开设计 |
| 通用港/国外港怎么设计？ | 三条强制线全球一致（SOLAS / IMDG / CSC），CTU Code 是共同的实务基准与尽职标准。**差异只在落地法规与检疫要求**（如澳洲检疫、美国 49 CFR） |

### 立刻可做的三件事

1. **把 60/50 规则做进算法与界面** —— 这是 CTU Code 最实用的一条，比显示"纵向偏移 4.999992%"专业得多，也更容易向评委解释
2. **重心目标从"贴住 5% 限值"改为"接近 0"** —— 60/50 规则的精神是重量集中在中间，不是推到边界
3. **把优化目标从"最大化利用率"改为"最小化柜数与总成本"** —— 这一步能让系统真正贴近货代的业务语言

## 附：一句话记住整个体系

> **三条强制线管"能不能上船"：重量（VGM）、危险品（IMDG）、箱体（CSC）。**
> **CTU Code 管"装得对不对"：60% 重量放中间一半，重心别超 ±5%，货要系固好。**
> **它不检查，但它在你出事的那一天出现——在法院和保险公司的桌上。**
