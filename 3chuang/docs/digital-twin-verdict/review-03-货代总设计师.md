## 一、业务自洽性矛盾表

| 矛盾点 | 正确做法（行业基准） | 不改的后果 | 风险 |
|---|---|---|---|
| **A1「整托零售箱组」(SKU-CTN-02)**：名字是"整托"，外观却判成纸箱散件(CARTON)、搬运方式写叉车、叉孔 NOT_APPLICABLE | 整托货包装类型应 = `PALLETIZED_CARTONS`，外观 = 托盘纸箱，叉孔 = 双向；名称、包装、搬运、叉孔四要素一致 | 操作员看到"叉车"去找叉孔，发现散件纸箱无孔，要么改人工摔货，要么叉车捅穿纸箱，现场立刻停摆打电话 | 高 |
| **A2「IPPC 木包装机件」(SKU-WOD-07) 与「加固工业模块」(SKU-HVY-08)**：搬运 = 叉车，但叉孔默认 NOT_APPLICABLE | 叉车搬运的木箱/工业模块必须申报底脚叉孔方向（或改吊装）；系统应在合规主流程强制"叉车 ↔ 叉孔非空" | 叉车司机看不到进叉接口，硬推刮坏木箱或改吊带，延误 + 货损，且 IPPC 木箱受损直接触发海关除害/退运 | 高 |
| **A3 21kg 托盘件、23kg 木箱被统一标"重货"**（`cargo.js:97` `heavy = weight >= 20`） | 重货/轻货是**积载密度 / 单件是否需机械且影响稳性**的概念，不是"≥20kg"。行业按人工搬运极限（约 25–30kg）、积载因数、是否需机械分别标注；21/23kg 单件绝不叫重货 | 回放面板把轻件和真正 208kg 模块同级标"重货"，操作员误判配载优先级，重心核算被噪音干扰 | 中（但这是**规则定义的原则性错误**，不是标注错） |
| **A4 名称与包装/搬运错位**："加固工业模块"标 reinforced → 木箱外观却叫模块 | 名称只是显示，系统应以 `packagingType` 为准并校验其与搬运、叉孔自洽 | 界面读着别扭，演示时评委一眼看穿"名实不符"，削弱信任 | 低-中 |
| **A5 可堆叠 ↔ 位置**：现有 `findPressureRisks` 能查"不可堆叠/易碎件被压" | 保持——但需对不可堆叠件顶部禁止回填做显式约束 | 无 | 低（逻辑已对） |

**区分**：A1、A4 是 DEMO 数据录入时把货设错类型导致的**表面错误**；A2 是数据完整性缺失（`forkInterface.js` 已有 `FORK_INTERFACE_UNVERIFIED` 校验，但 `evaluate.js` 合规主流程没把它当阻断）；**A3 是业务逻辑本身错了**——`weight>=20` 把"单件重量"和"重货积载属性"混为一谈，这是要命的。

## 二、口径一致性核查表

- **42 件 51.87% vs 212 件 79.43%**：差距合理。42 件是 20GP、三港 LIFO 必须把批次分区，空间被切碎；212 件是 40HQ、件小量大、易密铺。作为客户我会怀疑，但你们已有 `placementSpaceEvidence` 解释空区成因——**把空区成因甩给客户看，比只给一个利用率数字更能止疑**。
- **单位**：尺寸/净距用 mm、体积/余隙用 m³、重量用 kg 是行业惯例，可接受；但界面要把"mm / m³ / kg"标签写清，别让 667.695 mm 和 0.80 m³ 混着读。
- **虚假精度**：`667.695 mm` 精确到 0.001mm，而货物尺寸是整数 mm、求解是浮点——这是"看起来精确其实无意义"，应四舍五入到 mm 或注明"求解器浮点输出"。`0.80 / 4.52 m³` 余隙精度合理。
- **1,488 kg vs 8,623 kg** 是两案例各自总重，不是同一指标，界面必须标注案例来源，否则我一眼以为是同一票货的两个数。
- **后壁净距 0mm（42 件）vs 667.695mm（212 件）**：同一定义（深端到最近货面），一致。

## 三、作业可行性逐条裁决

1. **42 件 1,488kg 装 20GP，工人能不能干？** 能。但三港 LIFO 是真正卡点：汉堡靠门、安特卫普贴深端，工人必须严格分区，错一层就倒箱。51.87% 是 LIFO 的代价，不是算法差。
2. **第 4 件阻断人工装载，正确还是保守？** **正确且不过保守。** 人工堆到 1100mm 以上本就该上设备，系统要求验证高位设备/站位/支撑是负责任的。但现状是"阻断 = 方案未验证"，应明确告诉我**补哪几个设备参数**，而不是只说"停"。
3. **后壁净距 0mm 是好事还是风险？** 不是好事也不是坏事，**关键看系固**。0mm = 贴深端无缓冲，若没有绑扎/挡块，航行货移位是真实风险。系统只报"深端空隙待复核"却没给系固证据，**我不敢直接签**。
4. **重心 4.18% 通过，敢不敢签？** 在阈值内（横 <5%、纵 <10%），但 4.18% 已贴近横向预警线，且完全依赖真实称重。DEMO 数据下我接受计算值；**真实业务必须件件过秤，否则这数字我没法签字担责**。
5. **三港混装港序检查通过了吗？** 212 案例倒箱 0，说明求解器 LIFO 通过；42 件需确认同样通过。若不过，目的港倒箱 = 二次开封 + 工时 + 货损 + 滞期，现场会骂人。
6. **卸货推演没人员/设备，算废功能吗？** 原版是废功能；重构后已加实体卸货状态机（地牛/叉车/人工），**从"废"变"可用"**。但仍是"计算验证 ≠ 现场验收"，交付时我会标注"需现场复核"。

## 四、必须补齐的责任字段清单

- **VGM**：现仅有值 + 核实方法 + 托运人声明。**须补**：申报人、核实人、核实时间、承运人/码头申报状态与回执号、数据来源；并**明示"本系统仅更新本票记录，未向承运人或码头发送"**，引导对接 EDI。SOLAS 第 VI 章要求装船前申报 VGM，本地记录 ≠ 合规闭环。
- **木包装 IPPC**：须补责任方（托运人/报关行）、处置动作（提供 IPPC 标识照片或熏蒸证书）、复核人、复核时间——现在只有 WARNING，操作员点完不知道该干什么。
- **法规溯源**：Source Reader 的"核对时间 2026-09-10"必须区分"来源登记时间"与"本次核对时间"，并加核对人，否则我作为甲方会质疑结论真实性。
- **通用**：每个合规维度的责任方、复核人、复核时间、证据链 ID。

## 五、商业价值判断（含量化）

**省在哪**：① 配载方案自动化，替代人工算柜（约 30–60min/票 → 分钟级）；② LIFO/重心/系固一次算清，减少退关、倒箱、超载返场；③ 3D 回放用于客户确认与新人培训。

**量化（中等规模操作团队，日均 50 票）**：
- 配载工时节省 ≈ 50 票 × 0.75h × ¥50 × 300 天 ≈ **¥56 万/年**
- 避免每 100 票 1 次超载返场（¥3,000/次）≈ **¥1.5 万/年**
- 避免倒箱/滞期保守按 1 票/月 × ¥2,000 ≈ **¥2.4 万/年**
- **合计约 ¥60 万/年**

**我会为什么付钱**：为"可追溯合规证据链 + 实时 3D 回放 + 法规溯源"付钱；**不为"纯利用率数字"额外付费**——Excel、船司 e-Booking 配载、现有 TMS 装载模块都能给数字。本系统真正值钱的是数据/状态/语义孪生那三层，不是算法分。

**替代方案**：现有 TMS 装载模块 + 船司配载工具 + Excel。本系统凭"事实绑定 + 证据链 + 回放"才构成替代理由。

**试用拿哪票**：一票**真实三港 LIFO 的整柜**——这是最容易翻车也最能体现价值的场景，能直接验证港序、重心、系固三条命门。

## 六、业务侧修改清单（按 风险÷成本 排序）

1. **重货阈值规则**（`cargo.js:97` `weight>=20`）——**必须改**（原则性规则错）/ 规则问题 / 成本极低。**ROI 最高。**
2. **叉车 ↔ 叉孔一致性校验**：`handlingMethod=forklift` 时 `forkEntry` 必须非 `NOT_APPLICABLE`，并在 `evaluate.js` 主流程阻断——必须改（现场出事）/ 规则 + 界面 / 中成本。
3. **VGM 申报闭环**：补申报人/核实人/回执，明示"仅本地未发送"并预留承运人对接——必须改（合规不完整）/ 责任 + 对接 / 中成本。
4. **DEMO 数据包装类型修正**（整托零售箱组改 `PALLETIZED_CARTONS` 等）+ 名称 ↔ 类型 ↔ 搬运校验——应该改 / 数据 + 校验 / 低成本。
5. **后壁 0mm 强制系固/挡块证据**——应该改 / 界面表达。
6. **虚假精度（667.695mm）四舍五入**——应该改 / 界面表达 / 极低成本。
7. **卸货推演标注"计算验证非现场验收"**——应该改 / 界面。

**课程作业 vs 原则性错误边界**：A1/A4 的 DEMO 数据错、精度问题、卸货推演"计算 ≠ 现场"标注——这些属于**课程作业可接受的简化**，改了更专业但不致命；**A3 重货定义、A2 叉车 ↔ 叉孔缺失、VGM 不闭环**是**原则性错误**，不改就出事故或不能交付，必须拦下。
