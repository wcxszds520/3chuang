## 第 3 节　根因（已定位到具体代码行）

**抛出点**：`web-dashboard/src/three/cargo/PrecisionCargoFactory.js:25`

```js
export function placementAxisMap(item) {
  const explicit = item.axisMap;
  if (explicit && new Set([explicit.containerX, explicit.containerY, explicit.containerZ]).size === 3
    && [...].every(a => AXES.includes(a))) return explicit;
  const id = String(item.orientationId || item.orientation || '').toUpperCase();
  const code = /^[XYZ]{3}$/.test(id) ? [...id].map(a => ({ X:'L', Y:'W', Z:'H' })[a]).join('') : id;
  if (!/^[LWH]{3}$/.test(code) || new Set(code).size !== 3)
    throw new Error('货物缺少可验证的方向元数据');   // ← 在这里抛出
  return { containerX: code[0], containerY: code[2], containerZ: code[1] };
}
```

**触发链**：

```
TwinScene.jsx:717 / 1177 / 1302 / 1352 / 1605 / 1659
  → precisionBatchKey(item)
    → originalDimensionsM(item)
      → placementAxisMap(item)
        → 缺 orientationId / axisMap  → throw
```

**关键事实：`placementAxisMap` 只查两个字段，没有第三 fallback。**

### 契约断裂的证据（三方对照）

| 数据来源 | 是否带 `orientationId` / `axisMap` | 结果 |
|---|---|---|
| `industrial-production.jsx:6`（**sampleMode 展示数据**） | ✅ 显式带 `orientationId:'LWH'` + `axisMap:{containerX:'L',containerY:'H',containerZ:'W'}` | 能起来 |
| `three/visual/assetReview.js:73`（测试夹具） | ✅ 显式带 | 能起来 |
| **`domain/cargo/worksiteDemo.js`（42 件演示数据）** | ❌ **只有 `orientationPolicy:'FIXED_ORIENTATION'`，无编码字段** | **报错** |
| **`domain/cargo/cargo.js` 的 normalize 输出** | ❌ **产出 `orientationPolicy` / `orientationConstraints`，但从不产出 `orientationId` 或 `axisMap`** | 经 normalize 的数据全都不带 |

**并且测试把"缺编码就抛错"写成了期望**：
`PrecisionCargoFactory.test.js:105` → `expect(() => placementAxisMap({})).toThrow();`

### 结论

**这是一次「新校验器没有配套的数据迁移」造成的契约断裂：**

- Sep 11–15 引入的 `PrecisionCargoFactory`（高精度资产体系）要求**显式朝向元数据**
- 但上游 `cargo.js` normalize **没有同步产出该字段**
- 演示数据集 `WORKSITE_DEMO` **也没有**
- **只有 sampleMode 这条"展示专用路径"手工带了字段**

→ **后果：三维孪生对任何经过正常业务流的数据都起不来。** 三维孪生正是 CMIT「视觉效果 30 + 互动体验 30」的核心载体，**这是比 eta 更严重的 P0**。

## 第 4 节　修复方向（**未实施，待确认**）

### 方案 A（推荐）

在 `domain/cargo/cargo.js` 的 normalize 中**派生**朝向字段，而不是让下游靠猜：

| 情形 | 派生规则 | 依据 |
|---|---|---|
| `orientationPolicy === 'FIXED_ORIENTATION'`（不旋转） | `orientationId = 'LWH'` | 固定朝向 = 原始轴映射恒等。代入 `placementAxisMap`：code='LWH' → `containerX='L', containerY='H', containerZ='W'`，与 `originalDimensionsM` 的 `l→L, h→H, w→W` 完全一致 |
| 可旋转件 | **不在 cargo 层派生**，改在 **placement 归一化层**派生 —— 因为朝向由求解器逐件决定 | 一个 SKU 的不同件可能有不同朝向 |

### 方案 B（治标，不推荐）

给 `WORKSITE_DEMO` 等数据集补字段。**问题**：无法覆盖真实导入数据与外部数据集（`externalDatasets.js` 走的是 `orientation.policy`）。

### 建议的失败测试（先写测试再改）

```
1. normalize 一件 FIXED_ORIENTATION 货物 → 输出应含 orientationId='LWH'，且 placementAxisMap 不抛错
2. normalize 一件 FULL_ROTATION_ALLOWED 货物 → 不在 cargo 层写入固定编码（避免锁死可旋转语义）
3. WORKSITE_DEMO 全 42 件过 placementAxisMap 不抛错
4. 回归：sampleMode 数据仍正常
5. 反例：真正无法判定朝向的输入（如只有体积无三边尺寸）仍应抛错，不得被 fallback 掩盖
```
