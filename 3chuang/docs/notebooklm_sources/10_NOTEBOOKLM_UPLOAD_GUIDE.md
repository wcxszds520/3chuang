# 10_NOTEBOOKLM_UPLOAD_GUIDE

本文用途：告诉使用者应该把哪些 Markdown 和素材上传到 NotebookLM，以及如何设置自定义提示词，才能生成更稳的国赛答辩 PPT。

## 必传来源

建议优先上传以下 Markdown：

1. `01_PROJECT_OVERVIEW.md`
2. `02_PRESENTATION_STORYLINE.md`
3. `03_FACTS_AND_BOUNDARIES.md`
4. `04_PRODUCT_PAGES_AND_SCREENSHOTS.md`
5. `07_PPT_STYLE_AND_DESIGN_REQUIREMENTS.md`

这五份文件能让 NotebookLM 同时理解项目是什么、PPT 怎么讲、真实数据是什么、截图怎么用、视觉风格怎么控制。

## 可选来源

如果 NotebookLM 还能继续上传，建议加入：

1. `05_TECH_ARCHITECTURE.md`
2. `06_AI_VLM_RAG_3D_EXPLANATION.md`
3. `08_SPEAKER_SCRIPT_5_MIN.md`
4. `09_JUDGE_QA.md`

这些文件适合增强技术页、讲稿和答辩问答质量。

## 不建议上传来源

- `.env`、`.env.*`
- API Key、token、密钥相关文件
- `SECRET_ENV_CHECK.md`
- 旧版错误 PPT 或含过时口径的报告
- 未经筛选的代码文件
- 过大的截图全集
- 旧口径中包含 84.51%、本地规则 WARNING / AI建议 PASS / 人工复核独立、221/221 全部装入的材料

## 截图是否需要先转 PDF

如果 NotebookLM 支持图片来源，可以直接上传关键截图。如果上传数量有限，建议先用 6 到 8 张关键截图制作一个截图 PDF：

- 工作台
- 货物录入/VLM
- 柜型推荐
- 3D 作业孪生
- 合规预审
- 法规证据局部
- 报告导出
- E2E 终态

如果只生成 PPT 内容提纲，不需要上传所有图片；但如果希望它建议主视觉和截图布局，建议上传截图 PDF 或把 `04_PRODUCT_PAGES_AND_SCREENSHOTS.md` 作为来源。

## 哪些文件不要上传

不要上传任何包含密钥、环境变量、token、账号信息的文件。不要上传 `.env`。不要上传后端真实环境配置。不要上传没有清洗过的日志。

## 自定义演示文稿提示词

```text
请基于上传来源，为“甬柜易算”生成 13 页、16:9、适合中国国赛/创赛线上答辩的 PPT。目标不是验收报告，而是国赛作品叙事。页面结构必须遵守：封面、痛点、风险、方案闭环、工作台、VLM 录入、柜型推荐、3D 作业孪生、AI 与规则分工、合规预审与 RAG、真实联调证据、应用价值、收束页。每页一个核心观点、一个主视觉、少量关键点。风格为现代物流 SaaS + 港口数字孪生，清晰、稳重、专业、有科技感。不要廉价模板，不要每页几何卡片堆，不要文字爆炸。必须遵守真实口径：NB2026-DEMO-01、宁波港到汉堡港、40HQ、输入 221、已装入 221、未装入 0 件、空间利用率 84.51%、总重量 8,812 kg、合规 本地规则 WARNING / AI建议 PASS / 人工复核独立、VLM Qwen/Qwen3-VL-32B-Instruct、DeepSeek deepseek-v4-flash、RAG 为本地法规证据库。不要写任何过期演示数字，不要把 AI 建议写成最终结论，也不要写实时联网国标检索、完全自动化、替代人工、全球首创或零风险。第 8 页必须是视觉高潮，第 10 页必须体现合规体检 + 检查矩阵 + 证据链，第 11 页必须是真实链路时间线。
```

## 推荐生成模式

如果 NotebookLM 提供“详细演示文档”和“演示用幻灯片”选项，建议先选择“详细演示文档”生成结构，再让它压缩成“演示用幻灯片”。这样更容易控制事实边界和叙事逻辑。

## 生成后人工检查

生成 PPT 后需要逐页检查：

- 是否把 221/221 写错成 221/221。
- 是否出现 84.51% 或 本地规则 WARNING / AI建议 PASS / 人工复核独立。
- 是否把 RAG 写成实时联网。
- 是否把 AI 写成替代人工或直接决定坐标。
- 第 8 页是否足够像技术高潮页。
- 第 10 页是否有证据链，而不是大段法规截图。
- 第 11 页是否是真实链路时间线，而不是测试指标墙。
