# 甬柜易算第二阶段商业视觉与 3D 场景设计

日期：2026-07-10  
状态：目标文件已给出完整方向并明确要求直接执行；本文将其收敛为当前代码可实施的设计，不改变第一阶段业务契约。

## 1. 当前证据与用户目标

当前六页、统一订单会话、真实后端方案、合规三层证据、导出和 3D 作业状态机均可用。未修改基线为：Web lint 退出 0、56/56 单测、build 退出 0、核心 E2E 10 个证据点、3D motion 9/9、UI states 13/13。

新鲜视觉基线位于 `output/playwright/stage2-baseline/`。逐页检查确认：工作台偏静态、货物页末尾过空、柜型页解释重复、合规机械三等分、报告缺少 A4 文档层级，3D 默认仍是透明碰撞盒、无限网格、技术标签和逐件重复队列。

本阶段的用户结果是：专业、可信、克制、现代的港前装柜工作台；3D 应能让答辩观众一眼看懂箱门、叉车、当前货物、作业方向与真实装载目标。

## 2. 方案比较

### 方案 A：CSS 和文案补丁

只换标题、颜色、阴影和间距。改动小，但无法解决 3D 模型、模式、标签、相机构图、分组队列和页面信息结构。与目标文件明确禁止的完成方式冲突，不采用。

### 方案 B：受控视觉重构（采用）

保留现有 `Application`、会话、API、领域逻辑、状态机和 Three 坐标；在六个 workflow 页面、单一样式入口、`TwinScene` 及少量纯 UI 帮助模块中定向重构。所有新增行为先用纯函数单测锁定，原 E2E 不削弱。它能解决结构问题，同时把业务回归风险限制在可验证范围内。

### 方案 C：资产化 3D 重写

引入 glTF、重型场景库或重新组织作业状态机。视觉自由度高，但存在许可证、体积、加载、坐标与运动回归风险；仓库也没有已确认合适的本地资产。不采用。

## 3. 视觉语言

- 保留左侧深绿，但由近黑绿调整为较清透的港务深绿；导航活动态使用低饱和青绿面而不是厚重色块。
- 页面背景改为中性灰白，主工作区接近白色；暖米色只用于报告纸张、人工结论与轻提示。
- 主色、警告、严重风险沿用深绿、克制暖黄、低饱和红；不引入蓝色大屏、渐变、玻璃拟态或霓虹。
- 层级主要靠页面比例、字号、表面明度、对齐和内容分组；卡片只保留主任务、浮层和文档三类。
- 系统中文字体栈，不依赖外链；普通正文不小于 12px，主要业务文案保持投影可读。
- 所有 hover、focus-visible 和 disabled 状态清楚；动效尊重 `prefers-reduced-motion`。

## 4. 页面语言

六页 H1 固定为：

1. 工作台：`当前订单`
2. 货物：`货物清单与 SKU 管理`
3. 柜型：`柜型选择与装柜方案`
4. 3D：`3D 装柜作业`
5. 合规：`合规审查与人工复核`
6. 报告：`报告预览与交付`

副标题只说明当前任务。普通界面不再显示 `loadedCargo`、`local-block-preview`、`高 X`、`目标下角点`、`当前设备本地订单会话` 等内部词；这些信息只进入折叠的算法/调试详情。

## 5. 二维页面设计

### 工作台

- 顶部从订单号主标题改为“当前订单”，订单号、航线和船名进入紧凑上下文行。
- 流程条压低高度；当前方案缩略约 20%，保留关键四指标。
- 右侧继续承载下一步，但风险变为紧凑提示。
- 下方新增两列：活动时间线、待处理事项/方案版本。所有条目从当前 session、plan、AI、人工复核和未装件派生；没有状态时显示真实“尚未完成”，不伪造时间。
- 数据库历史继续折叠且明确是只读参考。

### 货物清单

- 表格仍为主视觉，桌面行高略压缩，1280 操作列保持可见。
- 目的港将 `Hamburg` 映射为“汉堡港”，原始技术值不丢失。
- 编辑、复制、删除使用可见的 hover/focus Tooltip 和 aria-label。
- 顶部来源改为“当前订单 · 已自动保存”。表格底部新增真实结束区：共 N 个 SKU、当前显示 M 个、件数和分页状态；不填充伪行。

### 柜型决策

- 标题与说明收敛，右栏标题为 `推荐 40HQ` 或 `已选择 40HQ`。
- 未装件形成紧凑但明确的风险区，并提供“查看未装货物”抽屉/对话框，数据直接来自真实 `unloadedCargo` 或输入差额。
- `PlanProjection` 增加轻量 `SKU / 港序 / 风险` 视图；图例可点击隐藏、hover 突出类别。它只改变 SVG 可见性和颜色语义，不改变坐标。
- 页面仍保留左预览、右解释、下方三柜型对比，不改成指标大屏。

### 合规审查

- 主栅格改为约 42% / 33% / 25%，移除透明大号 1/2/3。
- 结论条压缩；本地规则先显示 FAIL/WARNING，PASS 收进可展开区域。
- AI 区显示最近审计时间、来源和关键建议；人工区强调最新复核人、时间、备注与“追加复核”。
- 历史改为紧凑纵向时间线，避免空白横卡。

### 报告交付

- 预览按真实 A4 比例组织，具有页边距、纸张阴影、报告抬头、章节标题、页码和页脚。
- 章节导航为“装柜方案 / 合规摘要 / 法规证据 / 人工复核”，切换的是同一真实 report model 的预览内容。
- 装箱图缩为文档章节内容；右栏只保留 HTML、CSV、JSON 与打印，顶部主动作仍只有 HTML。
- 打印仍调用同一 `buildReportHtml`，不伪造 PDF/ZIP/XLSX。

## 6. 3D 页面结构

### 两种模式

- 默认 `作业模式`：箱体不透明、工业结构清楚，重点看门、叉车和当前货物。
- `复核模式`：靠相机侧壁和顶板采用受控半透明/剖切，明确显示“剖切复核”，开放已放货物、路径、重心和技术图层。
- 模式只改变渲染与 UI 图层，不改变 `OperationMachine`、真实目标或作业顺序。

### 页面比例

- 1920/1672：viewer 约 74%，右栏约 26%；标题压缩，控制固定在 viewer 底部，队列内部滚动。
- 1280：viewer 仍为主视觉，右栏缩窄但保持当前步骤与播放首屏可见。
- 右栏顺序：当前指令、分组队列、图层/调试折叠、风险记录。

## 7. 工业场景

### 集装箱

- 使用共享几何/材质建立底架、木色地板、左右侧壁、顶板、前壁、四角柱、上下边梁、门框、门槛和两扇门。
- 侧壁、顶板和门板使用轻量重复波纹 rib；重复结构优先 `InstancedMesh`。
- 作业模式为冷灰蓝不透明外壳、略亮内部；复核模式仍保留清楚轮廓，不降为透明线框盒。

### 门

- 左右独立 pivot、完整半幅门板、厚度、加强筋、铰链、锁杆、把手与闭锁件。
- 保持原开门进度和高 X 门端；门端相机采用偏置透视，使打开后的两块门板、门洞净空和叉车入口同时可见。
- 地面安全扇区仅作为可切换辅助，不成为默认技术图。

### 叉车

- 保留原 group、carriage、forks、wheels 接口，重做底盘、后配重、驾驶舱、顶棚、桅杆、货叉架、合理货叉、前后轮/轮毂、方向盘、前灯与警示灯。
- 车头/车尾、货叉与货物、车体与门洞的比例必须清楚；不引入外链或来源不明资产。

### 场地、灯光与阴影

- 无限网格移入调试图层；默认使用有限水泥地坪、黄色通道线、等待区、门前对准区、安全边界和少量仓库墙柱。
- Hemisphere + 主 Directional + 弱 Fill，使用克制 PCF 阴影和接触感圆形落影；不增加后处理、粒子或大型港口场景。

## 8. 标签、相机与队列

### 标签

- 默认只显示当前货物、目标位置和当前动作/阻断；区域名、路径节点、坐标和门端技术信息归入调试开关。
- 使用屏幕投影标签层：投影世界锚点、按优先级检测矩形重叠、纵向错位、边缘钳制、远距缩小/隐藏，相机变化时每帧重排。
- 纯函数单测覆盖重叠避让、屏幕边界和优先级；标签不得盖住叉车/当前货物主体。

### 相机

- 每个 preset 有独立 bounds、target、direction、up 和 margin，而不是同一 center 换方向。
- 总览覆盖完整箱体与作业区且主体占约 60–70%；门端聚焦门洞与叉车；侧视覆盖等待区到箱内路径；俯视覆盖门扇、路径、等待区和目标；跟随采用平滑目标和安全距离。
- 相机单测同时验证视锥安全和四个 target/preset 的独立性。

### 分组队列

- 新纯函数按 `SKU + 包装类别 + 港序 + 批次` 生成展示组，每件保留原 machine index。
- 组显示总数、当前件、港序、区域提示、完成数；默认折叠已完成组，当前/阻断组优先可见。
- 展开后显示真实步骤号、目标摘要、状态和阻断原因；支持跳至组和跳至件。
- 分组数组仅引用 `machine.queue`，绝不重排或修改状态机队列。

## 9. 性能与资源

- 保持单 RAF、delta-time、已放 `InstancedMesh`、当前货物独立 Mesh、ResizeObserver 单实例和完整 dispose。
- 波纹、门件、车轮、灯具和通道标识共享 geometry/material；不在每帧创建 geometry/material/texture。
- 标签 DOM 节点数量固定在默认 3 个以内；调试标签按需启用。
- 无重型物理、后处理、大模型或外部资源。

## 10. 验收设计

- 不删除或弱化 56 项 Web 单测、核心 E2E、3D motion 和 UI states 断言。
- 新增：页面语言/分组队列/相机 preset/标签布局/模式渲染元数据单测。
- E2E 增加作业/复核模式、默认不透明、调试网格默认关闭、四 preset 独立、分组展开/跳转、标签数量与重叠诊断。
- 最终脚本输出三视口七种页面状态（含 3D 两模式），并输出十类 3D 专项状态图。
- 每张最终图实际打开检查：空白、标题、重复、A4 感、箱体、门、叉车、地面、标签、构图、1280 可读性和录屏适配。

## 11. 错误处理与可访问性

- 原 loading/error/retry、Esc、遮罩、焦点返回和表单字段定位保持不变。
- 新切换器使用按钮组及 `aria-pressed`；分组队列使用 button/details 语义；Tooltip 不能替代 aria-label。
- 颜色不是唯一状态信号；模式、风险和完成状态均有文字。
- 截图只能发现对比、裁切和目标尺寸风险，不能证明完整 WCAG；键盘焦点、语义和 reduced motion 由源码审计与浏览器交互补足。
