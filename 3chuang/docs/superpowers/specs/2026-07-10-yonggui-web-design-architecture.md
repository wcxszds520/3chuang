# 甬柜易算 Web 产品级重构设计架构

日期：2026-07-10  
目标：把当前可运行原型收敛为可录屏、可复核、可长期操作的 2026 现代浅色物流 AI 工作台，并将 3D 作业孪生提升为项目核心演示页。

## 1. 设计决策

### 方案 A：继续视觉补丁

只在 `restore.css` 尾部追加覆盖，尽量不动 JSX。优点是短期改动少；缺点是当前已经有三套以上覆盖关系，断点和组件状态持续互相污染，无法稳定做像素级 QA。**不采用。**

### 方案 B：受控模块化重构

保留 App 内现有业务状态、API 调用、装箱算法入口和 Three.js 数据结构；逐页提取表现组件，建立单一产品样式入口；每完成一页删除该页旧样式。优点是风险可控、可分批验证，同时能真正解决维护和视觉漂移。**采用。**

### 方案 C：完整重写

重建路由、状态管理和 Three.js 场景。视觉自由度最高，但会扩大接口、算法、数据一致性和演示稳定性风险，也违背现有约束。**不采用。**

## 2. 产品定位

甬柜易算不是大屏驾驶舱，也不是营销官网。它是四类真实用户共用的港前装柜决策工作台：

- 中小卖家负责货物信息完整度。
- 货代配载员负责柜型和装柜方案。
- 仓库人员按 3D 作业单执行。
- 港前审核员复核风险、法规依据和交付报告。

每个页面必须回答三个问题：**当前订单发生了什么、下一步该做什么、这个结论如何复核。**

## 3. 信息架构

保留六个一级模块：工作台、货物录入、柜型推荐、3D 作业孪生、合规预审、报告导出。

统一页面骨架：

1. `PageHeader`：中文主标题、单句说明、最多两个操作。
2. `OrderContextBar`：当前订单、航线、柜型、数据来源、当前步骤。
3. `PrimaryWorkspace`：页面主任务区，占首屏最大面积。
4. `DecisionRail`：右侧建议、风险、证据或下一步。
5. `NextStepBar`：在需要串联流程的页面底部显示。

工作台只显示当前会话，不再混入数据库全局统计。系统健康、接口路径和表名移出用户首屏。

## 4. 视觉语言

### 色彩

- 页面底色：`#F4F7FB`
- 画布底色：`#EAF0F5`
- 卡片：`#FFFFFF`
- 主色：`#0F5CFF`
- 主色深：`#0040C8`
- 文字强：`#0A1422`
- 正文：`#1F2D3D`
- 次级：`#5A6B80`
- 边框：`#DCE5EF`
- PASS：`#0F7A3D`
- WARNING：`#B8451A`
- FAIL：`#B3231B`

不使用红金、深色、霓虹蓝紫、玻璃拟态或装饰性渐变。红色只表示严重风险。

### 字体

字体栈使用系统中文字体和 Inter 回退，不依赖远程字体。主标题 24px / 700，区块标题 16px / 700，正文 13px，表格 12px，关键指标 24px。所有字距统一为 `0`，不使用负字距和大写拉宽字距。

### 几何

- 页面 padding：22px
- 主区 gap：14px
- 卡片内边距：14px 或 16px
- 圆角：卡片 8px，输入与按钮 6px，标签 4px
- 阴影：只用 `0 3px 12px rgba(18,35,64,.05)`
- 边框优先于阴影，禁止浮层式卡片堆叠

### 动效

- 页面进入：180ms 透明度和 4px 位移
- 按钮：120ms 颜色和边框变化
- 状态更新：不超过 220ms
- 3D 自动播放：连续但低速，停止时画面稳定
- 尊重 `prefers-reduced-motion`

## 5. 响应式策略

- `>= 1440px`：三栏业务工作台；3D 为 `minmax(0,1fr) + 360px`。
- `1100px - 1439px`：两栏；主区与决策栏保留，次级信息移到下一行。
- `768px - 1099px`：单栏，但顶部订单条折成两行，主操作保持首屏可见。
- `< 768px`：侧栏变为紧凑顶部模块切换，不尝试在手机首屏完整展示 3D 操作台。

1672 × 941 是演示验收主视口；1280 × 720 是最低桌面验收视口。

## 6. 页面设计

### 工作台

恢复订单任务型工作台：四步流程、五个关键指标、最近任务、AI 建议、当前方案缩略、风险摘要、报告与法规入口。主视觉是“当前订单决策状态”，不是全局数据库统计。

### 货物录入

保持左表单、中 SKU、右 VLM/AI 三栏。订单条改为 SKU、件数、完整度、待补字段和资料状态。表格增加搜索、筛选、分页占位状态和可见操作列；VLM 明确真实调用状态，失败不显示成功。

### 柜型推荐

40HQ 推荐主卡必须使用当前真实算法结果。推荐理由解释“为什么仍推荐、哪些货物未装入、是否建议拆分或调整柜型”。CAD 预估区使用真实 `loadedCargo` 的轻量缩略，不再画固定示意矩形。

### 3D 作业孪生

3D 是核心页，采用两栏操作台：左侧为完整 viewer，右侧为当前作业和步骤队列。标题和订单条之后，剩余首屏高度全部给操作台。

场景构图规范：

- 集装箱主体占画面宽度约 70%。
- 门端、叉车路径和当前货物必须同时可见。
- 环境只保留地坪、少量港区构件和方向线，不让龙门吊抢主体。
- 总览相机根据容器包围盒和画布宽高计算距离，不使用固定倍数。
- 视角切换使用同一目标点和拟合函数，避免裁切。
- 货物继续使用 InstancedMesh；只为当前货物、风险货物和目标位添加独立轻量描边。
- A/B/C 区域、目标位和当前货物标记使用 Three.js Sprite 或可投影标签，不能用与相机无关的固定 CSS 坐标。
- 路径线、重心和未装入尾货来自当前 plan，不新增重后处理。

首屏 HUD 只保留装载进度、当前货物、作业动作、LIFO 和重心；约束命中条位于 viewer 底部。右栏上半部必须完整显示当前指令和三个操作，下半部显示队列、图层和风险摘要。

### 合规预审

明确三层信息：确定性规则检查、AI 合规解释、人工复核结论。分数环和矩阵使用同一个合规对象；AI 未运行时明确显示“待审计”，不能用本地规则冒充 AI 结论。RAG 标为本地法规证据库或联网参考，来源类型必须可见。

### 报告导出

中间主视觉为真实 HTML 报告预览，章节中嵌入当前方案缩略、合规矩阵摘要和证据数量。只展示真实可生成的 HTML、CSV、JSON；浏览器打印能力写“打印 / 另存为 PDF”，不展示无接口支撑的 PDF、ZIP、XLSX 下载。

## 8. 数据与错误状态

- 当前会话方案是六页唯一事实源。
- 后端方案、本地预演和 AI 审计必须显式标识来源。
- 接口失败保留用户输入并显示可重试错误。
- 无 plan 时显示空状态，不用静态数字填充。
- 任何下载按钮必须生成真实文件或禁用。

## 9. 验收标准

每一页必须完成：

1. `npm run build`
2. 1672 × 941 截图
3. 1280 × 720 截图
4. 与对应参考稿并排审查
5. 文本溢出与表格末列检查
6. 主要按钮交互检查

3D 额外验收：canvas 非空；总览、门端、俯视、侧视均不裁切容器主体；播放后当前货物变化；切页返回 canvas 仍可见；不新增 Bloom、God Rays 或粒子后处理。

## 10. 设计自审

- 无 `TBD`、`TODO` 或未定义页面。
- 视觉定位与浅色物流 AI 工作台一致。
- 没有把参考图当背景。
- 没有要求修改后端接口、装箱算法或 Three.js 数据结构。
- 已覆盖六页、壳层、响应式、动效、错误态和验证方式。
- 3D 的提升重点是镜头、层次、标签和作业叙事，不是炫技后处理。
- 代码拆分按页面渐进执行，不是一次性重写。

自审结论：**通过，可以进入分阶段实现。**
