## 二、关键突变说明（本轮 3 项，全部零违规通过）

1. **real-R1 组级朝向候选缓存**（FastBlockPackingEngine）：真实货代数据为逐单件展开（212 个 cargo 组），列构建每次拣选都对全组重算朝向候选。缓存后仅首算，热态 212 case 引擎耗时 38→32.5ms（中位）。
2. **real-R2 数据库懒加载连接池**（config/database.js 沙盒版）：原模块加载即建 MySQL 池并同步探活，给每次冷启动叠加固定开销与连接失败噪声；装箱引擎使用直接容器对象路径从不触库。改为首次 query 时才建池，冷启动 −11%（65.5→58.1ms 首测），并消除 ECONNREFUSED 噪声。
3. **real-R3 拣选池紧缩**（FastBlockPackingEngine）：`_pickPlannedItem` 每次全量扫描 portGroups（O(N²)）；对**全局耗尽**（quantity−nextUnitIndex≤0）的组惰性剔除并打标，未耗尽组不受影响（切片内 planned 耗尽不剔除，避免误伤后续切片）。212 case 热态中位再降 15%。

另有一次**失败突变已回滚**（详见 `mutation_failures.log`）：重柱居中实验（列按重量从截面中心向外分配）使 B 横向偏移 10.01%→13.74% 恶化，回滚至 best_real 前身检查点，其目标由上轮已交付的横向重心居中通道承担。

## 三、真实业务痛点处理结论

1. **托盘化重货（260kg、不可堆叠、叉车作业）**：`stackable=false` + 木托语义经注入的 normalizeCargoList 正确进入引擎约束；单 20GP 地板不足时按真实货代决策升 40HQ（或真实历史方案的分柜 9+7），全部合规装载。
2. **多客户追加装载**：customer/order/lot/unloadSequence 语义全链路透传至 placements；16 件双客户在 40HQ 单柜 100% 装载。多柜切分（2×20GP）经验证与真实历史方案一致为柜数最优（体积守恒下分柜数不变），单柜底座无需多柜规划器即可覆盖该决策。
3. **多港卸货顺序（LIFO）**：三港 212 件在批次区间 LIFO 契约下 100% 装载、0 违规；横向重心近零（0.09%），垂直方向重沉底成立（地板层为最重层）。
4. **纵向重心（遗留观察项）**：REAL-MULTIPORT-212 纵向 13.02%（COG_POLICY 警告级，非硬违规）：轻抛货港（seq1，86 件 5–35kg）居门侧、重货港（seq3，含 18 件 208kg）居深部的重量分布由批次 LIFO 契约决定，属货物构成固有；历史 hybrid-v2.5 参照方案为 9.999%（同样贴线），其代价是 22.7s 求解 vs 本底座 0.14s。

## 四、终局判定

**【达成完美装载】条件满足**：247/247 = 100% 件数装载（各 case 利用率均等于输入体积物理上限）、双验证器 0 违规、中位耗时 57.13ms ≤ 80ms（全样本中位 66.9ms）。另附:真实双跑布局逐 case 一致（确定性）。
