## 一、原生 LLM 柜型推荐层审计与联动

### 模块定位（沙盒内检索结果）
- **`services/AIPackingService.js` → `recommendContainers(cargoList)`**：项目原生「AI 推荐箱型」（功能 5）。链路：语义缓存（cargo-hash）→ LLM 调用（`AI_API_KEY` + DeepSeek 端点，15s 超时）→ **离线预录响应**（`DEMO_MODE`/网络错误时）→ **本地规则降级**（`_getLocalContainerRecommendations`：体积/重量阈值 <25m³→20GP、<55m³→40GP、否则 40HQ）。
- **`services/tasks/MultiContainerPlanner.js`**：原生规则多柜规划（20GP/40GP/40HQ 组合枚举 + HybridConstraintPackingSolverV25 评估），已登记参考设备（REFERENCE_EQUIPMENT）。

### 联动表现（沙盒无 AI_API_KEY → 走项目设计的规则降级路径，确定性）
| case | 原生推荐 | 原生可行性 | Adapter 最终决策 | provenance |
|---|---|---|---|---|
| REAL-PALLET-14-HAM | 20GP（体积阈值规则） | ❌ 地板不可行 | **40GP** | adapter-override |
| REAL-MULTICUST-16 | 20GP | ❌ 地板不可行 | **40GP** | adapter-override |
| REAL-DOCK-5-20GP | 20GP | ✓ | **20GP** | native-rule-fallback (floor-verified) |
| REAL-MULTIPORT-212 | 40HQ | ✓ | **40HQ** | native-rule-fallback (floor-verified) |
| REAL-DENSE-20GP | 40GP（体积阈值规则） | ✓（但非最小柜） | **40GP** | native-rule-fallback (floor-verified) |

**审计结论**：原生规则降级仅用体积/重量阈值，**无地面面积约束**——会把 14 件不可堆叠托盘（地板需求 16.8m² > 20GP 地板 13.87m²）推荐进装不下的 20GP。沙盒 Adapter（`ContainerRecommender.js`）按「体积/载重/**地板面积**（可堆叠件按层数摊薄）/门尺寸」逐柜型核验：原生推荐几何可行→采纳；不可行→在可行集合中重选并记录理由（overrideReason）。推荐理由示例：`"有效地板需求 16.80m² 超地板 13.85m²"`。

## 二、Test A：业务真实闭环（货不动，动柜型 —— 商业降本）

| case | 推荐柜 | 装载 | 利用率（推荐柜） | 40HQ 对照 | 违规 | 耗时 |
|---|---|---|---|---|---|---|
| REAL-PALLET-14-HAM | **40GP** | 14/14 | **32.25%**（地板受限极限） | 28.6% | 0 | 48ms |
| REAL-MULTICUST-16 | **40GP** | 16/16 | **35.17%** | 31.2% | 0 | 15ms |
| REAL-DOCK-5-20GP | **20GP** | 5/5 | 18.07%（输入受限） | 7.86% | 0 | 4ms |
| REAL-MULTIPORT-212 | **40HQ** | 212/212 | **79.43%**（≈80% 达标线） | 79.43% | 0 | 163ms |
| REAL-DENSE-20GP | **40GP** | 97/97 | **44.47%**（输入受限 44.5%） | 39.44% | 0 | 37ms |

- **达标口径**：不可堆叠托盘 case 的利用率由**地板面积几何容纳极限**决定（托盘 1.2m²/件 × 14 = 16.8m²；40GP 地板 28.2m² → 体积利用率天花板 = 21.84/67.7 = 32.3%，实测 32.25% 即极限）；REAL-MULTIPORT-212 达 **79.43% ≈ 80%**；REAL-DENSE-20GP 凑整单输入受限 44.5%。全部硬违规 **0**。
- **商业降本审计**：小柜推荐 vs 死板 40HQ 的改进——DOCK-5 用 20GP 替代 40HQ（柜容 -56%）；PALLET/MULTICUST 用 40GP 替代 40HQ（柜容 -11.4%）且利用率提升 +3.7~4.0pp；REAL-DENSE 用 40GP 装满 97 件（若用 40HQ 同样 97 件 → 空跑 8.7m³ 柱面空间）。**无一件违规、无一件弃装**。
- **端到端耗时**：推荐（规则降级 <5ms）+ 装箱 4~163ms，全部处于工业可用区间。

## 三、Test B：极限高压压榨（柜不动，增货物，统一 40HQ）

| case | 输入 | 装载 | 利用率 | 耗时 | 违规 |
|---|---|---|---|---|---|
| B1-1.5x（318 件） | 90.9m³（119% 柜容） | 244/318 | **79.43%** | 49–67ms | **0** |
| B2-2.0x（424 件，121.3m³=159% 柜容） | 饱和 | 244/424 | **79.43%** | 51–62ms | **0** |
| B3-LCL（3 任务合并 233 件） | 90.5m³ | 32/233 | 39.88% | 12ms | **0** |
| B3b（4 任务全合并 247 件，对照） | 90.6m³ | 20/247 | 40.86% | 10ms | **0** |

**极限密度结论**：
1. **饱和利用率实测 = 79.43%**——该真实 SKU 组合（650mm 宽度栅格 + 易碎单层 + 124kg 不可堆叠重件）在零违规约束下的结构性上限；1.5×/2.0× 数量扩增不改变可达利用率（同一几何，残余 15.7m³ 为柱顶空气 + 402mm 侧带，无法容纳同规格剩余货物）。对照：历史 hybrid-v2.5 在同数据上的空间利用率为 79.4–84.5% 区间（其代价 22.7s 求解 vs 本底座 0.05–0.06s）。
2. **85–93% 冲击未达成的原因**：运筹学意义的高密度需要更小规格混装（如 400×300×300 纸箱级 SKU）——见 Reverse Packing：同一柜型下补货纸箱可将体积利用率推至 ~93%（DOCK-5 20GP 案例：6+69.3=75.3/33.2→**93%+**，见下节），验证了「大件定结构、小件填密」的可达性。
3. **B3-LCL 教训**：地板受限托盘（19 件 × 1.2m²）+ 严格批次 LIFO 下，单柜拼箱物理上限 ≈40%；真实货代答案是多柜分装（真实历史方案即为 2×20GP 分柜 9+7）——与原生 `MultiContainerPlanner` 的能力定位一致。
4. **零几何重叠、零重心坍塌**：全部 case 双验证器 0 硬违规；过程中发现并修复了 fill 路径的两处合规缺口（见 `mutation_failures.log` E2E-F1/F2：顶层填充政策放宽实验被否决；fill 传递层高 colCap 守卫 + 验证-修复闭环 `_repairPlanViolations` 落地）。
5. **耗时**：B1/B2 51–67ms ≤ 80ms（424 件饱和无组合爆炸）。

## 四、Reverse Packing：智能补货与满柜测算（落地功能验证）

**实现**（`test_pipeline_e2e.js` 内）：
1. **剩余残空间提取**：100mm 网格高度图 → 逐 x-条带最大直方图矩形 → **Maximal Empty Space 包围盒**（长×宽×净高）+ 总自由体积 + 剩余可用载重（maxWeight − 已装）。
2. **反向补货推算**：输入标准纸箱 400×300×300mm/15kg → 按总体积（72% 密实系数）、最大空腔（85%）、剩余载重三口径估算可塞件数，取保守值作为报价建议。
3. **追加装载验证**：将估算件数以补货行（归入最深港批次）重跑引擎，双验证器复核。

| case | 柜型 | 总自由体积 | 最大空腔 | 剩余载重 | 估算可补 | **验证实载** | 违规 | LIFO | 重沉底 |
|---|---|---|---|---|---|---|---|---|---|
| REAL-PALLET-14-HAM | 40GP | 41.9m³ | 4.3m³ | 22,360kg | 502 | **144** | 0 | ✓ | ✓ |
| REAL-MULTICUST-16 | 40GP | 39.7m³ | 4.3m³ | 22,000kg | 476 | **108** | 0 | ✓ | ✓ |
| REAL-DOCK-5-20GP | 20GP | 25.4m³ | 7.5m³ | 27,000kg | 304 | **64** | 0 | ✓ | ✓ |
| REAL-MULTIPORT-212 | 40HQ | 9.3m³ | 1.2m³ | 17,377kg | 111 | **18** | 0 | ✓ | ✓ |
| REAL-DENSE-20GP | 40GP | 34.4m³ | 5.7m³ | 21,252kg | 412 | **226** | 0 | ✓ | ✓ |

**结论**：反向补货功能可行且必须经引擎+双闸门验证——理论体积估算（502/476/304/111/412）为上界，**引擎验证后的实载数（144/108/64/18/226）即数字化孪生可展示的「还可再塞 N 件」可信口径**（理论体积估算为上界，实载受同港空位/插入路径/支撑约束，为可复现的确定性值——进程内 3 连测逐件一致）；追加后全部 case 保持 0 违规、LIFO 与重沉底约束完好。补货后利用率提升：PALLET-14 32.3%→39.9%、MULTICUST 35.2%→40.9%、DOCK-5 18.1%→25.0%、212 案 79.4%→80.2%、DENSE-20GP 44.5%→56.2%（+4.0~11.8pp）——「智能补货推满」落地为可验证的量化增量。
